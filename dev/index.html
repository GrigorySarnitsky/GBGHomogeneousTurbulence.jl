GBGHomogeneousTurbulence.jl

GBGHomogeneousTurbulence.jl is a small, focused pseudospectral direct-numerical-simulation (DNS) package for homogeneous isotropic turbulence on a three-dimensional periodic domain: an incompressible velocity field $\boldsymbol{u}$ together with a single passive scalar $\varphi$, each optionally forced, advanced by a choice of integrating-factor time-stepping scheme, with Lagrangian particle tracking and field sampling.

It is built on GBGPeriodicFields, which supplies every field operation — transforms, differential operators, convolution, interpolation, and reductions. The GPU is the primary target, so each time step is in-place and allocation-free at field scale over preallocated buffers (occasional diagnostics allocate per call; the threaded CPU path spawns small per-pass task transients). Memory footprint on a GPU gives what a run needs on a card, and how CUDA's unified memory lets a run outgrow one.

Installation

This is a private, unregistered package. With repository access:

]add https://github.com/GrigorySarnitsky/GBGPeriodicFields.jl
]add https://github.com/GrigorySarnitsky/GBGHomogeneousTurbulence.jl

(the field-library backend first — both are unregistered, so Julia cannot resolve GBGPeriodicFields on its own — and Julia ≥ 1.12)

or

using Pkg

Pkg.add(url="https://github.com/GrigorySarnitsky/GBGPeriodicFields.jl")
Pkg.add(url="https://github.com/GrigorySarnitsky/GBGHomogeneousTurbulence.jl")

Then:

using GBGHomogeneousTurbulence

Quick start

Build a case with the Simulation constructor, which builds every component for you — spin it up to stationarity, and advance it:

using GBGHomogeneousTurbulence

sim = Simulation(grid_points_per_axis = 64)
# A 64³ forced-stationary run; ν is set so the grid captures the dissipation scale.

warmup!(sim)
# Spin up to statistical stationarity. The default forcing holds the injection rate
# the run was set up for, so k settles freely — see ConstantPower before measuring it.

t_end = current_time(sim) + 5.0
run!(sim) do s              # observe and advance: the callback reads the run,
    current_time(s) < t_end # records what it wants, and decides continuation
end

# The state is always current; the cache serves what the last iteration recorded
# at its end — a stale read throws rather than serving an old value.
kinetic_energy(sim.state.velocity_spectral)  # a measured observable, read off the state
velocity_physical(sim.cache)                 # the field the last iteration recorded
flow_parameters(sim)                          # the run's measured flow state

What it solves

With $\boldsymbol{u}$ the velocity, $\boldsymbol{\omega} = \nabla\times\boldsymbol{u}$ the vorticity, $\nu$ the kinematic viscosity, $\mathbb{P}$ the Leray–Helmholtz projection onto divergence-free fields, and $\boldsymbol{f}$ a forcing, the momentum equation is advanced in rotational form (its advective term carried by the Lamb vector $\boldsymbol{\omega}\times\boldsymbol{u}$),

\[\begin{aligned} \partial_t \boldsymbol{u} &= -\mathbb{P} (\boldsymbol{\omega}\times\boldsymbol{u}) + \nu\nabla^{2}\boldsymbol{u} + \boldsymbol{f}, & \nabla\cdot\boldsymbol{u} &= 0, \end{aligned}\]

and the passive scalar $\varphi$ by the advection–diffusion equation

\[\partial_t \varphi = -\nabla\cdot(\boldsymbol{u} \varphi) + \varkappa\nabla^{2}\varphi + f_\varphi,\]

with $\varkappa = \nu/\mathrm{Sc}$ the scalar diffusivity, $\mathrm{Sc}$ the Schmidt number, and $f_\varphi$ a forcing on the scalar. In both equations the diffusive (stiff) term is integrated exactly through an integrating factor, the nonlinear term explicitly by a Runge–Kutta stage combination, and the quadratic product is dealiased by the default $2/3$ rule (other strategies are available).

Work in progress

The package is being built in vertical slices. The coupled velocity + passive-scalar solver is in place, advanced by the integrating-factor schemes (IFLowStorageRK3, IFLowStorageRK4, IFSSPRK3 and IFHeun), with the forcing menu NoForcing, Linear, ConstantPower (the velocity default), VarianceController, VarianceRescaling, and StochasticOU, and Lagrangian particle tracking (Tracers). The reference turbulence laws (Phenomenology) provide usable model spectra, structure-function laws, and scaling constants. Accumulating statistics over the fields and the sampled trajectories is the caller's own analysis: GBGPeriodicFields supplies the field reductions and GBGStreamingStatistics the online estimators.

Components

Listed in build order — each module uses the ones above it. The API overview lists the same surface in reading order, leading with the run layer.

  • SimulationDomain: the discretized periodic box a run lives on — the FixedDomain, its choice of DealiasingStrategy, and the scratch-field allocators.
  • Observables: the measured functions of state — the energy and dissipation diagnostics of the flow and the scalar (including the fused pair kinetic_energy_and_dissipation), the developed-turbulence marker (derivative_skewness), the spectrum-derived scales, the CFL speed bound (max_speed), and the one field-valued observable, the vorticity recovery.
  • State: the evolving state (ResolvedFields, the single source of truth) a step advances, and the random initial conditions — a divergence-free velocity and a mean-zero scalar.
  • Cache: the ObservablesCache — where each iteration (one advance of the run; the notation page's vocabulary gives its full anatomy) leaves the observables it produced, read through checked reads that serve the deposited value or throw. Nothing is ever recomputed on a read.
  • Forcing: the interchangeable energy-injection strategies under AbstractForcing, chosen independently for the velocity and the scalar.
  • Generator: the flow's equations of motion — the rotational-form Navier–Stokes right-hand side, the passive-scalar advection, and the exact viscous integrating factor — gathered into one object, the ResolvedGenerator, which a scheme consumes through a fixed set of verbs — the protocol's functions prepare!, velocity_rhs!, scalar_rhs!, the two integrating-factor verbs and finalize! — rather than assembling the physics itself.
  • Propagator: the interchangeable integrating-factor schemes under AbstractIntegrator.
  • Particles: Lagrangian particle tracking — today the massless tracer — advection along trajectories and field sampling there, with selectable interpolation and particle integration schemes.
  • SimulationRun: the ergonomic run layer — Simulation, and the Courant–Friedrichs–Lewy (CFL) adaptive loop (advance! / run! / warmup!) that drives it. Read the state through sim.state, the deposited observables through sim.cache.
  • Phenomenology: the reference turbulence laws — model spectra, structure-function laws, and scaling constants — to validate a run against. A separate, opt-in group (not re-exported by the umbrella), designed to be extractable into a standalone package. In the actual include order this dependency-light leaf comes first; it is listed last here because a user's workflow reaches it last — validating against the laws comes after running.

Cache

GBGIsotropicTurbulence.Cache — Module
Cache

The observables cache — where the iteration leaves the observables it produces, for the run's own components and for any observation to read: a measurement the caller makes between iterations, from the values the run has already computed.

The cache's operations:

  • ObservablesCache — the cache itself: the slots, their epochs, and the two counters.
  • fields_modified!, particles_modified! — announce a mutation of the state or of the Tracers the run advects made outside the iteration, so the affected slots go stale and reads throw until the next deposit.
  • velocity_physical, vorticity_physical, scalar_physical — the checked reads of the cached fields (the velocity, vorticity, and scalar in physical representation).
  • max_speed — the cached largest flow speed, the number the timestep choice reads (one generic with the field reduction in Observables, whose docstring is the home).
  • velocity_at_particles — the checked read of the velocity sampled along each trajectory.

The field slots are filled by deposit!, which Propagator owns rather than this module because it needs the scheme's scratch to recover the fields. Each slot carries the value and the epoch that value belongs to, so a read can be refused rather than served stale.

The solver's side of the contract is that deposit! fills every field-derived slot at the iteration's end (the velocity-at-particles slot is filled by the same generic's particle form, after the tracer push) and sets its epoch. A caller reads through the accessors and deposits only to re-seed the cache after an out-of-band mutation it announced (fields_modified!); the iteration's own deposits are the solver's.

The cache keeps one epoch counter per dynamical factor — the resolved fields, the tracer positions — and a slot is readable exactly when its own epoch equals the counter it depends on.

An epoch counts changes to the state, not advances of the run: a completed step! advances the fields epoch, but so does any announced out-of-band mutation, so the two counts diverge. The epoch answers "is this value still the right one?"; the clock's current_step answers "how far has the run gone?".

The observables cache

The storage the iteration fills at its end with its observables — every read serves the deposited value or throws, and nothing is ever recomputed on a read.

GBGIsotropicTurbulence.Cache.ObservablesCache — Type
ObservablesCache(domain; scalar = false, number_of_particles = 0, history_depth = 1)

The observables cache of a run — the storage where each iteration deposits, at its end, the observables its own schedule produces: the velocity $\boldsymbol{u}$ and vorticity $\boldsymbol{\omega}$ in physical representation, the scalar $\varphi$ in physical representation when the run carries one, the fastest flow speed on the grid (the max_speed number the next timestep choice reads), and — when the run advects tracers — the flow velocity at the particle positions, $\boldsymbol{u}(t_n, \boldsymbol{X}(t_n))$.

The contents are automatic, derived from the configuration: the cache holds exactly what the iteration computes, materializes, and leaves alive at its end, and nothing more. The cache allocates and owns every slot, the velocity at the particles included — that sample is an observable of the flow, not particle state (a tracer has no velocity of its own), so its storage lives here and the tracer push writes into it exactly as the step writes into the field slots.

Build it on a FixedDomain domain. Simulation builds, wires, and seeds one for you; a hand-assembled run constructs it here.

Arguments

  • domain — the FixedDomain the run lives on; it sizes every slot.
  • scalar = false — pass true when the run evolves a passive scalar, which adds the scalar's slot.
  • history_depth = 1 — how many Lagrangian samples the run must be able to look back over, including the current one. A hand-assembled run sets it to history_depth(scheme) for its particle integration scheme. A one-step scheme needs 1 and stores no history; an order-step scheme needs order, and the scheme's register allocation refuses a cache built too shallow.
  • number_of_particles = 0 — the number of tracers the run advects; a positive count allocates the velocity-at-particles slot (an $M \times 3$ point-value section) and its sample history.

Read through the accessors — velocity_physical, vorticity_physical, scalar_physical, and max_speed — each of which returns the deposited value or throws. Nothing in the cache is ever recomputed: a read that finds a slot stale, taken (in use as the step's own scratch mid-iteration), or never deposited throws an ErrorException naming the slot and its state — a scheduling error whose only repair is to fix the schedule that failed to deposit.

A cached array is the next iteration's scratch

A slot is also the array its producer computes in: between deposits the step writes its own stage values there, so a cached field is meaningful only between iterations. Treat every returned array as read-only — it is the storage the next iteration will work in.

Fields

The word epoch names two things here, and these fields are of both kinds. The two counters tick as the state changes; every other *_epoch field records the counter's value at the moment its slot was filled. A slot is readable exactly while the epoch it records still equals the counter it depends on.

  • velocity_physical, vorticity_physical — the cached velocity and vorticity in physical representation. Mid-iteration the step also computes its stage recoveries into these same arrays, which is why they are not readable then.
  • scalar_physical — the cached scalar in physical representation, or nothing for a scalar-free run.
  • max_speed — the cached fastest flow speed (a host number in the field's own element type).
  • velocity_at_particles — the velocity sampled at the particle positions, or nothing for a tracer-free run.
  • velocity_at_particles_history — the earlier Lagrangian samples, most recent first, and history_steps the step sizes they were taken over; history_filled says how many are valid. A multistep particle integration scheme integrates over these; an announced reposition invalidates them together with the current sample.
  • velocity_epoch, vorticity_epoch, scalar_epoch, max_speed_epoch — the epoch each slot's value was deposited at, or a sentinel (never deposited / in use as scratch).
  • velocity_at_particles_fields_epoch, velocity_at_particles_particles_epoch — the velocity-at-particles slot's two epochs, against both counters, since that sample is a function of the state and the positions together.
  • fields_epoch — the resolved fields' counter: advanced by every completed step and by fields_modified!, so it runs ahead of current_step. A field-derived slot is readable exactly when its epoch equals this.
  • particles_epoch — the tracer positions' counter, advanced by every advect! push — the push announces itself — and by particles_modified! for a reposition made outside the push.

GBGIsotropicTurbulence.Cache.fields_modified! — Function
fields_modified!(cache)
fields_modified!(sim)

Announce that the resolved fields — $\hat{\boldsymbol{u}}$ and $\hat\varphi$, in spectral representation — were changed outside the iteration (a re-seeded velocity, any direct write to the state's storage). Advances the fields epoch of cache (an ObservablesCache), so every cached observable is stale and reads throw until the next deposit; that interval belongs to whoever made the change.

This verb is only for out-of-band changes — step! advances the epoch itself, and the closing deposit restores the cache. After a hand-made mutation, re-deposit with the Propagator's deposit! before advancing again — the timestep choice reads the cached maximum speed.

Coefficients written by hand must respect the real-field layout's conjugate symmetry — a violation makes spectral diagnostics silently disagree with the physical images. The sim form checks this: it measures the conjugate-symmetry residual on the planes that store both members of a pair and throws on an inconsistency beyond roundoff. The cache form cannot see the fields and trusts the caller; the package's own seeders satisfy the constraint by construction.

Given a Simulation it announces the change to that run's cache — the form to reach for when a run is what you are holding (particles_modified! offers the same pair of forms).

Returns its argument.

It also discards the Lagrangian sample history

Those samples are the velocity measured along the trajectory through the state being replaced, so a multistep particle integration scheme integrating over them would blend the old field into the new one. The run's own field advance is not such a change and keeps its history.

GBGIsotropicTurbulence.Cache.particles_modified! — Function
particles_modified!(cache)
particles_modified!(sim)

Announce that the tracer positions were changed outside the iteration (a reseed, a hand-written correction, any direct write to the tracer storage) — the particle counterpart of fields_modified!. Advances the particles epoch of cache (an ObservablesCache), so every trajectory-bound observable is stale and reads throw until the next deposit.

It also discards the Lagrangian sample history this cache carries, so a multistep particle integration scheme starts over from the new positions rather than integrating across the abandoned path. That is why the history lives here and not in the scheme's own registers: the object that owns the epoch owns the invalidation. The run's own tracer advance is not such a change and keeps its history.

A sanctioned push never needs this verb: advect! moves the particles epoch itself, a history-keeping announcement — the push extends the history this verb discards.

A hand-run loop that repositions tracers itself calls this and then makes the particle deposit — deposit!(cache, tracers, u) — from the deposited velocity, so the slot is refilled at the new positions. A loop announcing to a bare cache rather than a Simulation must also call restart! itself, for a scheme carrying its own registers: the Simulation form calls that for you; the bare-cache form cannot dispatch to it.

Given a Simulation it announces the change to that run's cache — the form to reach for when a run is what you are holding, mirroring deposit!'s own sim form.

Returns its argument.

The checked reads

Each accessor returns the observable deposited at the current epoch, or throws; the cached maximum speed is read through max_speed, documented with the reduction it stores.

GBGIsotropicTurbulence.Cache.velocity_physical — Function
velocity_physical(cache)

The velocity $\boldsymbol{u}$ in physical representation at the current epoch — the checked read of the ObservablesCache cache's velocity slot. Returns the deposited field when its epoch is current, and throws otherwise (the slot is mid-iteration scratch, stale, or was never deposited): the throw is an ErrorException naming the slot and which of the three states it is in, and nothing is ever recomputed on a read. Treat the returned field as read-only — it is the storage the next iteration works in.

GBGIsotropicTurbulence.Cache.vorticity_physical — Function
vorticity_physical(cache)

The vorticity in physical representation at the current epoch — the checked read of the ObservablesCache cache's vorticity slot, with exactly velocity_physical's contract (the deposited field or a throw; never a recomputation; read-only). The deposited value is produced by vorticity_physical! — measure with that function, read with this one.

source
GBGIsotropicTurbulence.Cache.scalar_physical — Function
scalar_physical(cache)

The scalar $\varphi$ in physical representation at the current epoch — the checked read of the ObservablesCache cache's scalar slot, on velocity_physical's terms (the deposited field or a throw; never a recomputation; read-only) plus one of its own: it throws an ArgumentError when the run carries no scalar, so there is no slot to read.

source
GBGIsotropicTurbulence.Cache.velocity_at_particles — Function
velocity_at_particles(cache)

The flow velocity at the particle positions, $\boldsymbol{u}(t_n, \boldsymbol{X}(t_n))$, at the current epoch — the $(M, 3)$ array ($M$ the tracer count) of the velocity sampled at the position each tracer occupies at that instant: the genuine Lagrangian velocity the statistics accumulate. Treat the returned array as read-only — it is the cache's own slot, and the tracer advance writes into it mid-iteration. The checked read of the ObservablesCache cache's velocity-at-particles slot: it serves the deposited values or throws an ErrorException, like every cached read — the sample depends on the state and the positions, so it is current only when both counters match its own. Throws an ArgumentError when the run advects no tracers.

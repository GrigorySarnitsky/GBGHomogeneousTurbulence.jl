Particles

GBGHomogeneousTurbulence.Particles — Module
Particles

It holds Lagrangian particles, today the massless tracer, and what is measured at them:

  • Tracers — the tracer set: the positions (a PointSet), a selectable interpolation scheme, and opt-in unwrapped positions read by unwrapped_positions.
  • interpolate_at_particles! — read a field at the particle positions; new_vector_point_values / new_scalar_point_values allocate the output buffers it fills.
  • ParticleTrail — the last few samples of one quantity at the particles, each with its time; time_derivative! and time_derivative differentiate it in time along the trajectories. The run keeps one for the velocity, read through velocity_at_particles_trail.
  • ParticleTraversal — the memory-locality order the gathers visit the tracers in, a value-preserving accelerator; rebuild_traversal! refreshes it from the current positions.
  • write_tracers / read_tracers and write_trail / read_trail — the HDF5 persistence of a tracer set and of a trail, each as one self-describing group (available once HDF5 is loaded).

The schemes that advance the positions are in ParticlePropagator.

The tracer set

Tracer positions plus a selectable interpolation scheme, with the accessor that reads the unwrapped positions. The set holds trajectory state only.

GBGHomogeneousTurbulence.Particles.Tracers — Type
Tracers(domain; number_of_particles, interpolation_scheme, unwrapped = false,
        rng = default_rng())
Tracers(domain; positions, interpolation_scheme, unwrapped = false)

A set of Lagrangian tracers, built on domain's backend and element type.

Give exactly one of the two. The number_of_particles form seeds that many tracers uniformly at random in the periodic box. The positions form supplies the tracer positions as a GBGPeriodicFields PointSet, copied to domain's backend and element type. Supplying both, or neither, raises an ArgumentError, and so does a raw array in place of the PointSet: coordinates cross into the package only through the GBGPeriodicFields point types.

The interpolation_scheme is the GBGPeriodicFields scheme used to evaluate the velocity — and any sampled field — at the tracer positions. CatmullRom is the $C^1$ choice and Simulation's default; it is a ready-made value rather than a type, so it is passed bare. LalescuSpline and LagrangeSpline offer higher smoothness or interpolation order at a wider stencil — useful for derivative-sensitive readouts such as acceleration statistics. Each takes its stencil width in grid points per axis (CatmullRom is LalescuSpline(4)), and LalescuSpline also takes its order of continuity as the smoothness keyword.

Arguments

  • domain — the FixedDomain whose backend, element type and box the set is built on.
  • number_of_particles — seed this many tracers uniformly at random in the box.
  • positions — or copy this PointSet in instead; give exactly one of the two.
  • interpolation_scheme — the scheme used to evaluate a field at the tracer positions.
  • unwrapped = false — set to true to also track the winding-preserving unwrapped positions unwrapped_positions serves; the wrapped positions stay the dynamical state either way.
  • rng — the random stream seeding the positions (used with number_of_particles, ignored with positions); defaults to Random.default_rng().

Examples

A run carries tracers when Simulation is given a count; advance! then advances them with the fields and records the Lagrangian velocity each iteration, so both reads below are current between iterations:

sim = Simulation(grid_points_per_axis = 64, scalar = PassiveScalar(),
                 particles = ParticleTracking(number_of_particles = 4096))
advance!(sim)

# the (M, 3) positions, via GBGPeriodicFields
X = point_positions(sim.tracers.positions)
# u(tₙ, X(tₙ)), the Lagrangian velocity — throws if stale
v = velocity_at_particles_trail(sim.cache)[0].value

out = new_scalar_point_values(sim.tracers)  # allocate once, then reuse every iteration
interpolate_at_particles!(out, scalar_physical(sim.cache), sim.tracers)

Building a set directly, to place tracers deliberately rather than at random, takes the positions form, and a run adopts the set through ParticleTracking:

tracers = Tracers(domain; positions = PointSet([0.1 0.2 0.3; 1.0 1.0 1.0]),
                  interpolation_scheme = CatmullRom)
sim = Simulation(domain; particles = ParticleTracking(tracers))

Read the particle state straight off the struct's own fields — the positions are PointSets, and raw arrays and counts come from GBGPeriodicFields' point_positions and npoints, never from accessors of this package. Passing unwrapped = true additionally tracks the winding-preserving unwrapped positions unwrapped_positions serves — the wrapped positions stay the dynamical state either way. The velocities are a deposited observable, not tracer state: the particle form of deposit! writes them into the run's observables cache at the end of each iteration, and velocity_at_particles_trail reads them there.

Fields

  • positions — the tracer positions, as the PointSet every operation takes: the one storage, always wrapped — the dynamical state. GBGPeriodicFields' point_positions serves its (M, 3) matrix view, with $M$ the tracer count.
  • interpolation_scheme — the scheme used to evaluate a field at the tracer positions.
  • unwrapped_positions — the opt-in unwrapped positions (unwrapped = true) as a PointSet, advanced by every push with the same displacement terms but never reduced to the box; nothing when untracked. Read it through unwrapped_positions.
source
GBGHomogeneousTurbulence.Particles.unwrapped_positions — Function
unwrapped_positions(tracers)

The unwrapped positions of the tracer set tracers, as a PointSet — the trajectory with its winding kept, each coordinate the literal sum of every displacement since seeding, never reduced to the periodic box. These are the positions a mean-square-displacement or dispersion diagnostic needs: those are functions of the displacement $\boldsymbol{X}(t) - \boldsymbol{X}(0)$, with $\boldsymbol{X}$ a tracer's position, which box-wrapped positions cannot supply across a crossing. Accumulating such statistics over them — on the raw (M, 3) array GBGPeriodicFields' point_positions extracts — is the caller's analysis.

The unwrapped positions exist only when the tracer set was built with unwrapped = true; reading an untracked set throws an ArgumentError (which is why this throwing read exists while the plain state is read straight off the struct's fields). The wrapped positions remain the dynamical state either way — the dynamics always advance wrapped, since a coordinate that grows with winding loses absolute floating-point resolution, while the unwrapped positions only ever feed differences, whose relative accuracy the growth does not touch.

Sampling at the particles

Read any physical field at the particle positions, for the Lagrangian statistics.

GBGHomogeneousTurbulence.Particles.interpolate_at_particles! — Function
interpolate_at_particles!(out, field, tracers; traversal = nothing) -> out

Sample a physical field at the current tracer positions. This is how a field is gathered along the trajectories; what is then accumulated over those values is the caller's own analysis.

Arguments

  • out — the point-value buffer written: a VectorPointValues for the velocity, a ScalarPointValues for the scalar $\varphi$.
  • field — the field in physical representation.
  • tracers — the tracer set, whose positions and interpolation scheme are used.
  • traversal = nothing — a ParticleTraversal, to gather in its memory-locality order (on a run, sim.particle_traversal); nothing gathers in tracer order, with identical values.

The trail of a quantity

The last few samples of one quantity at the particles, each with its time, and its time derivative along the trajectories. A run keeps a trail of the velocity itself, read through velocity_at_particles_trail; a caller keeps one for any other quantity.

GBGHomogeneousTurbulence.Particles.ParticleTrail — Type
ParticleTrail(allocator, tracers, capacity)

The last few samples of one quantity at the particles, each kept with the simulation time it was taken at — the record a time derivative along the trajectories is computed from (time_derivative!). A sample is the quantity's value at every particle together with its time. The trail keeps at most capacity of them, and adding one to a full trail drops the oldest: it serves derivatives, and a long history is the caller's to keep, more sparsely.

Arguments

  • allocator — a function of tracers that returns one fresh point-values object: new_scalar_point_values or new_vector_point_values. It is called capacity times, so the trail owns all of its storage and adding a sample allocates nothing.
  • tracers — the Tracers the values are sized to.
  • capacity — the largest number of samples kept, at least 1.

A sample is read by its offset in steps from the newest: trail[0] is the newest, trail[-1] the one before it, and each is a named pair, trail[-1].time and trail[-1].value. A positive index, or one further back than the samples present, is an ArgumentError. length(trail) is the number of samples present, and iteration runs from the oldest to the newest. A value is the trail's own storage, to be read and never written.

A sample is added with push!, which hands the storage to a function to fill — here a do block — and labels it with the time t, which must be later than the newest sample's. If the function throws, no sample is added, and a full trail has by then given up its oldest:

push!(trail, t) do value
    interpolate_at_particles!(value, field, tracers)
end

The trail a run keeps for the velocity, read through velocity_at_particles_trail, is filled by the run alone and refuses push!.

Examples

The scalar along the trajectories and its rate of change, sampled once per iteration:

trail = ParticleTrail(new_scalar_point_values, sim.tracers, 3)
rate = new_scalar_point_values(sim.tracers)
run!(sim) do s
    push!(trail, current_time(s)) do value
        interpolate_at_particles!(value, scalar_physical(s.cache), s.tracers)
    end
    length(trail) == 3 && time_derivative!(rate, trail)
    current_step(s) < 100
end

Fields

These are the trail's internals; read a trail through its indexing, never through them.

  • values, times — the slots of the ring, one point-values object each, and the time of the sample in each.

  • newest, filled — the slot of the newest sample, and how many slots hold one.

  • cache_owned — whether the trail is a run's own, which push! refuses.

  • nodes, weights — host scratch of time_derivative!.

GBGHomogeneousTurbulence.Particles.time_derivative! — Function
time_derivative!(out, trail; order = 1) -> out

The time derivative of the quantity a ParticleTrail holds, at the time of its newest sample: writing $f(t)$ for the quantity at one particle along its trajectory, $\mathrm{d}^{m}f/\mathrm{d}t^{m}$ at $t_n$, with $m$ the order. For the run's velocity trail and $m = 1$ this is the Lagrangian acceleration.

It is the derivative of the polynomial through all the samples present, taken at their actual, possibly uneven times. With $d$ samples spaced $\Delta t$ apart the error is of order $\Delta t^{d - m}$, so the trail's capacity bounds the accuracy and a higher derivative needs a longer trail.

Arguments

  • out — the point-values object written, of the same kind as the trail's values and not one of them.
  • trail — the ParticleTrail to differentiate; it must hold at least order + 1 samples, or the call is an ArgumentError.
  • order = 1 — the order $m$ of the derivative; 0 copies the newest value.

The weights are computed on the host from the samples' times, by Fornberg's recursion, and the values are combined in one pass over the particles, without allocating at their scale.

source
GBGHomogeneousTurbulence.Particles.time_derivative — Function
time_derivative(trail; order = 1)

The time derivative of the quantity a ParticleTrail holds, at the time of its newest sample, in a newly allocated point-values object: the allocating form of time_derivative!, whose docstring states what is computed and how accurately.

Arguments

  • trail — the ParticleTrail to differentiate; one that holds no sample is an ArgumentError.
  • order = 1 — the order of the derivative; 0 returns a copy of the newest value.

The traversal order

The memory-locality order the gathers visit the tracers in — a value-preserving accelerator: the interpolated values are bit-identical with or without it, only the visiting order changes. A run builds and refreshes it for you (the traversal_mode of a ParticleTracking); the type and its rebuild verb are here for a caller refreshing on a chosen cadence from a run! callback.

GBGHomogeneousTurbulence.Particles.ParticleTraversal — Type
ParticleTraversal(domain, tracers; automatic = true)

The memory-locality order in which a field is gathered at the tracers — a PointTraversalOrder over the tracer set tracers on the grid of domain (a FixedDomain), together with the scratch that lets it be rebuilt in place. Tracers seeded at random, or mixed by the flow, visit the grid in no order at all, so each interpolation stencil is a cache miss; visiting them tile-by-tile turns the gather into a sweep, and GBGPeriodicFields' interpolate! accepts such an order through its traversal keyword. The order only reorders the visits — it changes no value, so a run with and without it produces bitwise-identical trajectories and samples.

A run builds one for you: the traversal_mode of its ParticleTracking decides whether, and whether the run or the caller rebuilds it. A caller's own gather takes it through the traversal keyword of interpolate_at_particles!; on a run, that is sim.particle_traversal.

Arguments

  • domain — the FixedDomain whose grid the tiles are laid over.
  • tracers — the Tracers whose positions are ordered; the order is sized to their count and built from their current positions.
  • automatic = true — whether a run rebuilds the order every iteration (true) or leaves the rebuilding to the caller, through rebuild_traversal! (false). A rebuild costs a small fraction of the gather it accelerates, so every iteration is the default; a stale order is never wrong, only progressively less useful as the flow mixes the tracers away from it.
One order serves every gather of the step

GBGPeriodicFields accepts any same-length order for a point set of the same count, so the one order built from the tracer positions is also passed to the gather at the predicted positions a Heun step makes; those sit a step's displacement from the tracers, well inside the tiles the order groups.

Fields

  • order — the PointTraversalOrder: one Int32 index per tracer, a permutation of the visits.
  • scratch — the PointTraversalOrderScratch the in-place rebuild sorts in: the per-tracer tile keys and the per-tile counts and offsets.
  • automatic — whether a run rebuilds the order every iteration.

GBGHomogeneousTurbulence.Particles.rebuild_traversal! — Function
rebuild_traversal!(traversal, domain, tracers) -> traversal
rebuild_traversal!(sim) -> sim

Rebuild the tracer traversal order from the current tracer positions, in place.

Arguments

  • traversal — the ParticleTraversal to rebuild.
  • domain — the FixedDomain whose grid the order is taken on.
  • tracers — the tracer set whose positions are ordered.
  • sim — a run (Simulation), in the second form: the traversal it carries as sim.particle_traversal is rebuilt.

Call it from a run's callback when the run was built with traversal_mode = :manual, at whatever cadence you choose — every so many steps with every_steps, or every so much time with every_time. With the default automatic mode the run rebuilds every iteration and the call is never needed. The rebuild allocates nothing at the tracer scale; a run without a traversal order refuses the call with an ArgumentError.

Wiring tracers into a run

Give Simulation a ParticleTracking and the run carries a tracer set: advance! pushes it every iteration and records the Lagrangian sample, so the reads below are always current between iterations.

sim = Simulation(grid_points_per_axis = 64,
                 particles = ParticleTracking(number_of_particles = 4096))
warmup!(sim)
advance!(sim)

point_positions(sim.tracers.positions)     # (M, 3) positions, via GBGPeriodicFields
trail = velocity_at_particles_trail(sim.cache)   # throws if stale
trail[0].value                             # the sample u(tₙ, X(tₙ)), and trail[0].time its time
out = new_vector_point_values(sim.tracers)   # allocate once, then reuse
interpolate_at_particles!(out, velocity_physical(sim.cache), sim.tracers)

Forcing

GBGIsotropicTurbulence.Forcing — Module
Forcing

The interchangeable energy-injection strategies, concrete AbstractForcing subtypes. A strategy acts on the step through up to four methods, each defaulting to doing nothing:

  • set_forcing_rate! — a linear forcing rate folded into the integrating factor; uses_linear_rate declares that a forcing supplies one.
  • apply_forcing! — a post-step projection or rescale.
  • prepare_forcing! — a per-step internal-state advance.
  • add_forcing_source! — an additive per-stage source.

The strategies are NoForcing, BandRescaling, Linear, and ConstantPower; one implementation serves both the velocity (a vector field) and the scalar (a scalar field), through tensor-order-generic field operators. The velocity and scalar are forced independently: FlowConditions takes a separate velocity_forcing and scalar_forcing (each an AbstractForcing), so a run can force the velocity while the scalar decays freely, force both, or leave either unforced.

An operator-free keyword constructor (BandRescaling(; …), Linear(; …), ConstantPower(; …)) returns a DeferredForcing that a Simulation materializes once the domain exists.

Forcing strategies

The forcing supertype and its concrete strategies: the unforced baseline, deterministic band rescaling, and the two linear-rate forcings. One implementation serves either the velocity or the scalar.

GBGIsotropicTurbulence.Forcing.AbstractForcing — Type
AbstractForcing

Supertype of the energy-injection strategies. A strategy may implement any of set_forcing_rate! (a linear forcing rate folded into the integrating factor), apply_forcing! (a post-step projection), prepare_forcing! (a per-step state advance), and add_forcing_source! (an additive per-stage source); all default to doing nothing, and a strategy owns whatever scratch its hooks need.

The hooks form one per-step lifecycle with a fixed order: prepare_forcing! and set_forcing_rate! run once before the Runge–Kutta stages (the state a later hook consumes must be prepared here), add_forcing_source! runs at every stage, and apply_forcing! runs after the completed step. The linear rate and the additive source are two channels of one forcing term — the part linear in the field is folded exactly into the integrating factor, the remainder is added at the stages — so a single strategy may legitimately use both.

GBGIsotropicTurbulence.Forcing.BandRescaling — Type
BandRescaling(domain; target, over = :band, lowest_shell = 1, highest_shell = 2)

Deterministic rescaling forcing (post-step) that holds a field's amplitude fixed. Each step the in-band Fourier modes (integer shells $\texttt{lowest\_shell} \le \kappa \le \texttt{highest\_shell}$ of $2\pi/L$) are rescaled by a single factor to hold the target.

The target is the observable the forcing holds, chosen to agree with the diagnostics: the kinetic energy $\tfrac{1}{2}\langle\lvert\boldsymbol{u}\rvert^{2}\rangle$ (kinetic_energy) for the velocity, the scalar variance $\langle\varphi^{2}\rangle$ (scalar_variance) for the scalar — the field's $L^{2}$ observable, carrying the $\tfrac{1}{2}$ only for the vector.

The over keyword selects where the target applies:

  • :band (default) — hold the band's own value; the whole-field value then floats, oscillating slowly about its mean as the band feeds the cascade.
  • :total — rescale the band to absorb the whole-field deficit so the whole-field value equals target (for the velocity this pins the r.m.s. velocity $u'$ and hence $\mathrm{Re}_\lambda$). If the out-of-band value alone exceeds target, the band is zeroed (the closest reachable state).

Rescaling preserves the divergence-free constraint either way.

A deterministic clamp, not a faithful stationary sampler

Holding an amplitude fixed by deterministic rescaling is the Berendsen-thermostat limit of stochastic velocity rescaling: it has no conserved quantity, is not associated with a well-defined ensemble except in limiting cases, and suppresses the physical fluctuations of the quantity it holds (Bussi, Donadio & Parrinello 2007). Use it to spin up or to pin an amplitude; when the held quantity is itself measured, prefer a fixed-injection forcing (ConstantPower), which leaves the energy free to fluctuate.

GBGIsotropicTurbulence.Forcing.Linear — Type
Linear(domain; rate, lowest_shell = 1, highest_shell = 2)

Linear (negative-damping) forcing $f = A \texttt{field}$ in a low-wavenumber band (a band-limited variant of Lundgren 2003, whose linear forcing acts at every wavenumber), with the fixed rate $A = \texttt{rate}$ on shells $\texttt{lowest\_shell} \le \kappa \le \texttt{highest\_shell}$. The rate is folded into the integrating factor (exact for the linear term), so the forced band modes grow at net rate $A - D\lvert\boldsymbol{\kappa}\rvert^{2}$ ($D$ the field's diffusivity). A positive rate amplifies the field.

source
GBGIsotropicTurbulence.Forcing.ConstantPower — Type
ConstantPower(domain; target, lowest_shell = 1, highest_shell = 2)

Constant-injection-rate forcing: a banded linear forcing $f = A \texttt{field}$ on integer shells $\texttt{lowest\_shell} \le \kappa \le \texttt{highest\_shell}$ of $2\pi/L$ (default 1–2), whose rate $A$ is set each step so the field's injection rate holds the target. In stationarity the injection balances dissipation, so target is the dissipation rate, chosen to agree with the diagnostics: dissipation $\varepsilon$ for the velocity, scalar_dissipation $\varepsilon_\varphi$ for the scalar. The rate is folded into the integrating factor; like Linear, it preserves a solenoidal velocity.

Deferred forcing

The operator-free deferred form a strategy's constructor returns, materialized into a concrete forcing once the domain exists.

GBGIsotropicTurbulence.Forcing.DeferredForcing — Type
DeferredForcing

A deferred forcing. The operator-free keyword constructors — Linear(; rate, …), ConstantPower(; target, …), and BandRescaling(; target, over, …) — return a DeferredForcing capturing the same keywords as their domain-taking forms (the band lowest_shell / highest_shell, and BandRescaling's over); it is materialized into the concrete AbstractForcing once the FixedDomain exists (done for you by Simulation). A forcing argument therefore accepts either a ready-built AbstractForcing (from the domain-taking constructor) or a DeferredForcing.

Forcing methods

The four step methods a strategy may implement (each a no-op by default), listed in the order step! fires them, followed by the trait that declares a strategy supplies a linear rate — part of implementing set_forcing_rate!, since the generator allocates a rate array only where one is declared.

GBGIsotropicTurbulence.Forcing.prepare_forcing! — Function
prepare_forcing!(forcing, field, domain, dt) -> nothing

Update a forcing's internal state once per step, before the Runge–Kutta stages, from the start-of-step field (in spectral representation) and the timestep dt, on the FixedDomain domain. A stateful forcing owns whatever scratch this needs. The default does nothing.

source
GBGIsotropicTurbulence.Forcing.set_forcing_rate! — Function
set_forcing_rate!(forcing, rate, field, domain) -> Bool

For a forcing linear in the field, fill the per-mode rate rate — a scalar field in spectral representation holding real values — with $A(\boldsymbol{\kappa})$ (the forcing $f = A \texttt{field}$) and return true; the integrator folds it into the diffusive integrating factor $\mathcal E(\boldsymbol{\kappa})$ (see velocity_factor), so the forced modes advance at the net linear rate $A(\boldsymbol{\kappa}) - D\lvert\boldsymbol{\kappa}\rvert^{2}$ ($D$ the field's diffusivity). Return false (the default) when the forcing contributes no linear rate. The field is the start-of-step field in spectral representation; domain is the FixedDomain.

source
GBGIsotropicTurbulence.Forcing.add_forcing_source! — Function
add_forcing_source!(forcing, nonlinear, domain) -> nonlinear

Add an additive forcing source to the dealiased nonlinear-term buffer nonlinear at each Runge–Kutta stage (the source is held fixed over the step, so it integrates at the scheme's order), on the FixedDomain domain. The default does nothing.

source
GBGIsotropicTurbulence.Forcing.apply_forcing! — Function
apply_forcing!(forcing, field, domain) -> field

Apply a post-step forcing to field (a velocity or scalar $\varphi$ field in spectral representation) in place, on the FixedDomain domain. The default does nothing; see BandRescaling.

source
GBGIsotropicTurbulence.Forcing.uses_linear_rate — Function
uses_linear_rate(forcing) -> Bool

Whether forcing drives its field through a linear per-mode rate — that is, whether it implements set_forcing_rate!. false by default; a forcing that does implement the hook must declare it true.

The generator allocates a rate array $A(\boldsymbol{\kappa})$ per field only for a forcing that declares this, so an unforced field, a post-step projection, or a stochastic source carries no rate storage at all. Declaring it is therefore part of implementing set_forcing_rate!, not an optimization: a forcing that fills a rate without declaring one is never given an array to fill, and the constructor rejects it rather than let the forcing go silently unapplied.

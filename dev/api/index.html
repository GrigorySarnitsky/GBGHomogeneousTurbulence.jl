API overview

The package is an umbrella module (GBGHomogeneousTurbulence) assembled from submodules. Its re-exported submodules build on one another in the order SimulationDomain → Observables → State → Cache → Forcing → Generator → Propagator → Particles → SimulationRun; the extraction-bound Phenomenology leaf leads the include order but is not re-exported (reach it opt-in). The pages below are ordered for reading, not by that dependency: SimulationRun comes first because a run is what a user builds first, and the pieces it composes follow. The umbrella re-exports the public surface of the listed submodules, so using GBGHomogeneousTurbulence brings everything into scope.

  • GBGHomogeneousTurbulence: the top-level module and public re-export surface.
  • SimulationRun: the ergonomic run layer — Simulation, and the Courant–Friedrichs–Lewy (CFL) adaptive loop (advance!, run!, warmup!) that drives it. Read a run's state through sim.state and its deposited observables through sim.cache.
  • SimulationDomain: the discretized periodic box a run lives on — the FixedDomain (with its choice of DealiasingStrategy), the scratch-field allocators, and the two band edges, max_retained_wavenumber and max_resolved_wavenumber.
  • State: the evolving state (ResolvedFields — the velocity and scalar in spectral representation, the single source of truth) and the random initial conditions that seed it — a divergence-free velocity and a mean-zero scalar.
  • Observables: the measured functions of state — the energy and dissipation diagnostics of the flow and the scalar (including the fused pair kinetic_energy_and_dissipation), the developed-turbulence marker (derivative_skewness), the spectrum-derived scales, the CFL speed bound (max_speed), and the one field-valued observable, the vorticity recovery.
  • Cache: the ObservablesCache — where each iteration leaves the observables it produced, read through checked reads that serve the deposited value or throw. Nothing is ever recomputed on a read.
  • Forcing: the interchangeable energy-injection strategies under AbstractForcing, chosen independently for the velocity and the scalar.
  • Generator: the flow's equations of motion — the rotational-form Navier–Stokes right-hand side, the passive-scalar advection, and the exact viscous integrating factor — gathered into one object, the ResolvedGenerator, which a scheme consumes through a fixed set of verbs.
  • Propagator: the integrating-factor time-stepping schemes under AbstractIntegrator — the low-storage IFLowStorageRK3 and IFLowStorageRK4, the Shu–Osher IFSSPRK3, and IFHeun (Heun).
  • Particles: Lagrangian particle tracking — today the massless Tracers; advect! under a selectable particle integration scheme (Heun default, AdamsBashforth available), and interpolate_at_particles! for the Lagrangian statistics.
  • Phenomenology: the reference turbulence laws — model spectra, structure-function laws, and scaling constants — to validate a run against. A separate, opt-in group: not re-exported by the umbrella, and designed to be extractable into a standalone package.

Propagator

GBGIsotropicTurbulence.Propagator — Module
Propagator

The interchangeable time-marching schemes, concrete AbstractIntegrator subtypes; a run chooses one as the integrator of its Simulation. All are of the integrating-factor family: the stiff diffusive part is advanced exactly and the nonlinear term explicitly by a Runge–Kutta stage combination.

  • IFLowStorageRK3 (the default), IFRK2 — the schemes (RK3 low-storage; IFRK2/Heun a cheaper two-stage alternative, imaginary-axis unstable).
  • IntegratorBuffers, allocate_buffers — the preallocated per-step scratch.
  • step! — advance the coupled velocity and passive scalar one timestep.
  • recommended_cfl — a scheme's advective-CFL ceiling.

Integrator schemes

The integrating-factor scheme supertype and its concretes — the default third-order low-storage RK3, then the cheaper, imaginary-axis-unstable second-order Heun.

GBGIsotropicTurbulence.Propagator.AbstractIntegrator — Type
AbstractIntegrator

Supertype of the time-marching schemes. A scheme implements step!(integrator, state, generator, domain, buffers, derived, dt), advancing the state's velocity $\hat{\boldsymbol{u}}$ and scalar $\hat\varphi$ (both in spectral representation) by one timestep in place, and may specialize recommended_cfl.

source
GBGIsotropicTurbulence.Propagator.IFLowStorageRK3 — Type
IFLowStorageRK3()

Integrating-factor third-order low-storage Runge–Kutta (Williamson 1980, 2N-storage). With the diffusive integrating factor $\mathcal{E}_D(\tau)$ built by the generator's velocity_factor! / scalar_factor! over a substep interval $\tau$ ($D = \nu$ for the velocity, $\varkappa = \nu/\mathrm{Sc}$ for the scalar) and $\widehat{\boldsymbol{N}}$ each field's right-hand side, the step carries a state $\hat q$ and a single accumulator $\boldsymbol{h}$ through three stages $i = 1,2,3$,

\[\begin{aligned} \boldsymbol{h} &\leftarrow A_i \boldsymbol{h} + \Delta t \widehat{\boldsymbol{N}}(\hat q), \\ \hat q &\leftarrow \hat q + B_i \boldsymbol{h}, \\ \hat q &\leftarrow \mathcal{E}_D(d_i\Delta t) \hat q, \\ \boldsymbol{h} &\leftarrow \mathcal{E}_D(d_i\Delta t) \boldsymbol{h}, \end{aligned}\]

with $A = (0, -5/9, -153/128)$, $B = (1/3, 15/16, 8/15)$, and node increments $d = (1/3, 5/12, 1/4)$ (abscissae $c = (0, 1/3, 3/4)$). The velocity and scalar are advanced in lockstep (the same $A,B,d$), each with its own diffusivity, and any post-step forcing is applied after the third stage. Three nonlinear evaluations per step, two field registers per field — the default workhorse: third-order and stable on the imaginary axis (limit $\sqrt{3}$), unlike IFRK2.

source
GBGIsotropicTurbulence.Propagator.IFRK2 — Type
IFRK2()

Integrating-factor second-order Runge–Kutta (Heun). With the velocity and scalar integrating factors $\mathcal{E}_\nu$ and $\mathcal{E}_\varkappa$ (the generator's velocity_factor! / scalar_factor! at $D = \nu$ and $D = \varkappa = \nu/\mathrm{Sc}$ over the step $\Delta t$) and $\widehat{\boldsymbol{N}}$ each field's right-hand side, one step of a field $\hat q$ with integrating factor $\mathcal{E}$ is

\[\begin{aligned} \hat q^{*} &= \mathcal{E} (\hat q_n + \Delta t \widehat{\boldsymbol{N}}_1), \\ \hat q_{n+1} &= \mathcal{E} \hat q_n + \tfrac{\Delta t}{2}(\mathcal{E} \widehat{\boldsymbol{N}}_1 + \widehat{\boldsymbol{N}}_2), \end{aligned}\]

with $\widehat{\boldsymbol{N}}_1$ at $\hat q_n$ and $\widehat{\boldsymbol{N}}_2$ at the predictor $\hat q^{*}$; velocity and scalar use $\mathcal{E}_\nu$ and $\mathcal{E}_\varkappa$ respectively, then the forcings are applied. Two nonlinear evaluations per step.

Note

Every second-order two-stage explicit Runge–Kutta has stability function $R(z) = 1 + z + z^{2}/2$, for which $\lvert R(\mathrm{i}y)\rvert^{2} = 1 + y^{4}/4 > 1$: the scheme is unstable on the imaginary axis, so it is stable only where the viscous damping of the integrating factor dominates. It is adequate for well-resolved, modest-Reynolds-number runs but is not the default — prefer IFLowStorageRK3 for high Reynolds number or marginal resolution.

Step scratch

The preallocated per-step working set the integrator writes into — built per concrete scheme, sized so a step allocates no field-sized memory.

GBGIsotropicTurbulence.Propagator.IntegratorBuffers — Type
IntegratorBuffers

The preallocated per-step scratch the integrator writes into, sized so a step allocates no field-sized memory. Built per scheme by allocate_buffers(integrator, domain; scalar), which allocates exactly that scheme's working set: a register another scheme would use is left nothing, never allocated.

Fields

Shared — every scheme allocates these:

  • vorticity_physical, velocity_star — the substage velocity/vorticity registers in physical representation (the start-of-step fields come from the run's ObservablesCache observables).
  • stage1 — the first Runge–Kutta stage register (the accumulator for IFLowStorageRK3, the first stage for IFRK2).
  • integrating_factor — the register the exact linear subflow is written into each substep.

Scheme-specific — allocated only for the scheme that uses it, else nothing:

  • nonlinear — the assembled right-hand side (IFLowStorageRK3 only).
  • stage2, velocity_star_spectral — the second stage register and the substage velocity predictor $\hat{\boldsymbol{u}}^{*}$ in spectral representation (IFRK2 only).

Nested:

  • scalar — a ScalarBuffers for the passive scalar $\varphi$ when scalar = true, else nothing; when nothing, the run evolves no scalar and none of its field-sized buffers are allocated.

The right-hand-side assembly scratch (the quadratic products, the phase-shift buffers, the forcing-rate arrays) lives with the generator, on the ResolvedGenerator — the buffers here are only the scheme's own stage registers.

source
GBGIsotropicTurbulence.Propagator.allocate_buffers — Function
allocate_buffers(integrator, domain; scalar = false) -> IntegratorBuffers

Allocate the IntegratorBuffers integrator needs, dispatching on the concrete scheme so it allocates exactly its working set — never a register another scheme would use. IFLowStorageRK3 allocates stage1 and nonlinear; IFRK2 allocates stage1, stage2, and velocity_star_spectral. scalar = true adds the nested ScalarBuffers, likewise sized to the scheme. A scheme with no method here is a hard error — there is no over-allocating fallback. The run layer calls this when assembling a Simulation.

Time stepping

One in-place step of the coupled velocity and passive scalar together through the shared RK stages.

GBGIsotropicTurbulence.Propagator.step! — Function
step!(integrator, state, generator, domain, buffers, derived, dt)

Advance the state (a ResolvedFields holding the velocity $\hat{\boldsymbol{u}}$ and passive scalar $\hat\varphi$ in spectral representation) by one timestep dt in place, using the integrator, the reified generator (a ResolvedGenerator — the equations of motion, their conditions, and their assembly scratch), the domain, the scheme's buffers, and the run's observation cache derived (a ObservablesCache). Dispatches on the concrete integrator type (see IFRK2, IFLowStorageRK3).

A scheme does only stage arithmetic: it opens the step with the generator's prepare!, evaluates the right-hand sides and exact linear factors through the generator protocol at each stage, and closes with the generator's finalize! — it never assembles the physics itself. The start-of-step velocity and vorticity in physical representation are read through derived's accessors — recomputed automatically when stale, so a hand-run loop needs no manual refill — and the cache's fields epoch is advanced when the step completes, marking every cached observable for recomputation on its next read.

Timestep ceiling

A scheme's advective-CFL ceiling.

GBGIsotropicTurbulence.Propagator.recommended_cfl — Function
recommended_cfl(integrator, domain)

A conservative advective-CFL ceiling $C$ for the scheme, for a timestep $\Delta t = C \Delta x / \max_i\lvert u_i\rvert$.

The advective eigenvalues of the dealiased system are imaginary, of magnitude up to $\kappa_{\max}\sup\lvert\boldsymbol{u}\rvert$; stability needs this times $C$ to stay within the scheme's imaginary-axis stability limit $y_{\mathrm{s}}$. The timestep divides by the cheaply-measured maximum component $\max_i\lvert u_i\rvert$ (within a factor $\sqrt3$ of $\sup\lvert\boldsymbol{u}\rvert$); that gap is absorbed by the conservative factor below, since the eigenvalue bound itself over-estimates the true spectral radius (not every mode carries the peak speed). The base ceiling is calibrated for the $2/3$ rule ($\kappa_{\max}\Delta x = 2\pi/3 \approx 2.09$): for IFLowStorageRK3 $y_{\mathrm{s}} = \sqrt{3}$ gives $C \lesssim 0.83$, taken conservatively as $0.5$; IFRK2 is imaginary-axis unstable ($y_{\mathrm{s}} = 0$, relying on viscous damping), so a small $0.25$.

It scales that base by the domain's dealiasing: a strategy that keeps modes to a higher $\kappa_{\max}$ (e.g. HouLi, out to the Nyquist wavenumber) takes a proportionally smaller step, $C \propto 1/\kappa_{\max}$. This is the value Simulation uses; override cfl for a specific run.

Forcing

GBGIsotropicTurbulence.Forcing — Module
Forcing

The interchangeable energy-injection strategies:

  • AbstractForcing — the strategy supertype, defining the four-hook lifecycle below.

A strategy acts on the step through up to four methods, each defaulting to doing nothing, listed in the order the step calls them:

  • prepare_forcing! — advance the forcing's own internal state, once per step.
  • set_forcing_rate! — supply a steady linear rate, folded into the integrating factor; uses_steady_linear_rate declares that a forcing supplies one.
  • add_forcing_source! — add a source term at each stage.
  • project_forcing! — project or rescale the field after the step.

DeferredForcing is the operator-free keyword form of a strategy, materialized once the Simulation has built the domain — a construction-time object, not a lifecycle hook.

The strategies, one implementation each serving both the velocity and the scalar through tensor-order-generic field operators:

  • NoForcing — leave the field undriven.
  • Linear — a fixed linear rate on a band.
  • ConstantPower — a band amplitude re-solved each stage to hold the injection rate.
  • VarianceController — drive the field's variance to a target by feedback; the default.
  • VarianceRescaling — hold a band's amplitude by deterministic rescaling, at first order.

Which keywords carry defaults follows one test: does the value come from the method, or from this run? A canonical band (lowest_shell = 1, highest_shell = 2) is the method's and defaults; what a run holds fixed — target, rate, over — has no canonical value and is required. A default never hides a choice you needed to make.

A band reaching above the dealias cutoff is inert there — the mask holds those modes empty, and a band forcing multiplies the field — so construction warns about it.

The two fields are forced independently: FlowConditions takes a separate velocity_forcing and scalar_forcing, so a run can force one, both, or neither.

Forcing strategies

The forcing supertype and its concrete strategies, grouped by the route each takes through the step — which is what decides whether it preserves the scheme's order. Linear supplies a steady rate folded into the integrating factor, exactly and for free. ConstantPower and VarianceController supply rates that track the state, so they enter the right-hand side at every stage. VarianceRescaling rescales after the step, which is operator splitting and first-order by construction. One implementation serves either the velocity or the scalar.

GBGIsotropicTurbulence.Forcing.AbstractForcing — Type
AbstractForcing

Supertype of the energy-injection strategies. A strategy may implement any of prepare_forcing! (advance the strategy's own internal state — a stochastic forcing's random process, say — never the simulation state), set_forcing_rate! (a rate that is constant in time, folded into the integrating factor — a strategy implementing it must also declare uses_steady_linear_rate, or it is never given a rate array to fill), add_forcing_source! (an additive per-stage source), and project_forcing! (a post-step projection); all default to doing nothing, and a strategy owns whatever scratch its hooks need.

The hooks form one per-step lifecycle with a fixed order: prepare_forcing! and set_forcing_rate! run once before the Runge–Kutta stages (whatever internal state a later hook consumes must be prepared here), add_forcing_source! runs at every stage, and project_forcing! runs after the completed step. The rate and the source are two channels of one forcing term — the steady part is folded exactly into the integrating factor, the remainder is added at the stages — so a single strategy may legitimately use both.

Which channel a rate may take is decided by steadiness in time, not linearity in the field: the integrating factor holds a rate fixed for the whole step, so one re-solved from the state must go through add_forcing_source! instead. The declaration is measured at construction, not trusted.

Each mutating hook returns its mutated argument (set_forcing_rate! the rate, add_forcing_source! the right-hand side, project_forcing! the field); prepare_forcing! returns nothing.

One instance per forced field, for a strategy that carries state

A strategy holding per-field scratch or a random stream must not drive both fields from one instance, or their bookkeeping is conflated; FlowConditions throws an ArgumentError rather than let that happen. A stateless strategy — one whose whole content is its band and its target — has nothing to conflate and may be shared.

GBGIsotropicTurbulence.Forcing.Linear — Type
Linear(domain; rate, lowest_shell = 1, highest_shell = 2)

Linear (negative-damping) forcing $f = A \texttt{field}$ in a low-wavenumber band (a band-limited variant of Lundgren 2003, CTR Annual Research Briefs, which carries no DOI — whose linear forcing acts at every wavenumber), built on the FixedDomain domain. The rate is folded into the integrating factor, so the forced band modes grow at net rate $A - D\lvert\boldsymbol{\kappa}\rvert^{2}$ ($D$ the field's diffusivity).

It is the only strategy taking that route — exactness there is a statement about a steady $A$ — which makes it the cheapest forcing here, at no per-stage reduction and no host readback.

Arguments

  • domain — the FixedDomain the band is built on.
  • rate — the fixed linear rate $A$. A positive value amplifies the field.
  • lowest_shell = 1, highest_shell = 2 — the forced band, as integer shells in units of the box's fundamental $2\pi/L$.

Fields

  • indicator — the band indicator as a real array.
  • rate — the fixed linear rate $A$.

GBGIsotropicTurbulence.Forcing.ConstantPower — Type
ConstantPower(domain; injection_rate, lowest_shell = 1, highest_shell = 2)

Constant-injection-rate forcing, built on the FixedDomain domain: a banded linear forcing $f = A \texttt{field}$ on the integer shells lowest_shell to highest_shell (in units of the box's fundamental $2\pi/L$; default 1–2), whose rate $A$ is set each step so the field's injection rate holds the injection_rate. A linear rate injects at $2 A E_{\mathrm{band}}$, with $E_{\mathrm{band}}$ the band's own observable, so the rate that holds it is

\[A = \frac{\texttt{injection\_rate}}{2 E_{\mathrm{band}}}.\]

In stationarity the injection balances dissipation, so injection_rate is the value $\varepsilon$ relaxes to in the stationary mean — chosen to agree with the diagnostics — the rate $\varepsilon$ for the velocity (measured by dissipation) and $\varepsilon_\varphi$ for the scalar (by scalar_dissipation). The keyword names the kind of quantity it is — a rate, where VarianceRescaling's target is an amplitude.

Since that amplitude is re-solved from the state, it enters the right-hand side at every stage rather than the integrating factor, where freezing it would cost the scheme its order. Like Linear it is a per-mode multiple of the field, so it preserves a solenoidal velocity.

Arguments

  • domain — the FixedDomain the band is built on.
  • injection_rate — the rate at which energy (for the velocity) or scalar variance (for the scalar) is injected; not an instantaneous dissipation the forcing measures or clamps.
  • lowest_shell = 1, highest_shell = 2 — the forced band, as integer shells in units of the box's fundamental $2\pi/L$.
An empty band is left alone, not driven infinitely hard

The rate $A$ diverges as the band's own value goes to zero — its energy for the velocity, its variance for the scalar — which is reachable: a scalar seeded with nothing in the forced shells, or the step after a VarianceRescaling(over = :total) zeroed the band. Below a small floor on $E_{\mathrm{band}}$ the amplitude is set to zero, so an empty band stays empty rather than taking an unbounded kick; seed content in the band if a run needs the forcing to take hold.

Fields

  • band — the band-pass kernel, lazy: the per-stage source both weights the band observable with it and convolves against it, so no indicator array is stored.
  • injection_rate — the held rate.

GBGIsotropicTurbulence.Forcing.VarianceController — Type
VarianceController(; target, gain = 1, turnover_time = nothing,
                   lowest_shell = 1, highest_shell = 2)

Hold the field's variance at target by feedback — the kinetic energy $k$ for the velocity, $\langle\varphi^{2}\rangle$ for the scalar — with the constant-$k$ controller of Bassenne, Urzay, Park & Moin (2016, doi:10.1063/1.4944629).

Prefer it to VarianceRescaling whenever accuracy in time matters, which is nearly always: it enters the right-hand side as a smooth rate the scheme integrates, keeping the order the scheme advertises, where a rescaling is a post-step projection that caps the iteration at first order.

The rate is the marginal law $A = \varepsilon/2k$ plus a proportional restoring term:

\[A(\boldsymbol{\kappa}, t) = \frac{\varepsilon(t) - G[k(t) - k_\infty]/t_\ell}{2k_f(t)} \quad\text{in the band, } 0 \text{ outside,}\]

so that $\mathrm{d}k/\mathrm{d}t = -G(k - k_\infty)/t_\ell$ exactly: the variance relaxes exponentially to a stable attractor with settling time $t_\ell/G$.

The limit gain = 0 is the bare marginal law, and it is allowed: exact reinjection of the instantaneous $\varepsilon$ makes $\mathrm{d}k/\mathrm{d}t = 0$, so $k$ is conserved at its initial value and target never enters the rate. Every level is then a neutral equilibrium — the reinjection cancels the cascade's own restoring response, which ConstantPower's fixed injection retains — so discrete integration bias accumulates uncorrected (about 1% of $k$ per 1000 steps, measured at $24^3$), and nothing ever restores it.

The two variances there are not interchangeable: $k$ is the whole field's, the one held; $k_f$ the forced band's, dividing out because the forcing injects only there.

The mechanism is the one molecular dynamics settled on for the same problem: holding a quantity by per-step rescaling is the naive thermostat, feedback inside the equations is the Nosé–Hoover move, and gain-limited relaxation toward a target is Berendsen weak coupling (Berendsen et al. 1984, doi:10.1063/1.448118), whose deterministic-rescaling limit is VarianceRescaling.

Arguments

  • target — the whole-field variance $k_\infty$ to hold, in the field's own convention: the kinetic energy for the velocity, $\langle\varphi^{2}\rangle$ for the scalar.
  • gain = 1 — the dimensionless gain $G$. Larger relaxes faster (Bassenne report $O(1-10)$); 0 is the bare marginal law above.
  • turnover_time = nothing — the large-eddy turnover time $t_\ell$. When omitted it is taken as $2k_\infty/3\varepsilon_\infty$ with $\varepsilon_\infty$ the stationary estimate for this box, the same estimate the grid-mode viscosity solve uses.
  • lowest_shell = 1, highest_shell = 2 — the forced band, in integer shells of $2\pi/L$.
The settling time, not the gain, is the physical parameter

Only the ratio $t_\ell/G$ is observable: it is how long the variance takes to return after a disturbance. The two are kept separate because that is how the source states them.

Fields

  • band — the band-pass kernel, lazy; the controller convolves against it and stores nothing.
  • target, gain, relaxation_time — $k_\infty$, $G$ and $t_\ell$.

GBGIsotropicTurbulence.Forcing.VarianceRescaling — Type
VarianceRescaling(domain; target, over, lowest_shell = 1, highest_shell = 2)

The deterministic rescaling forcing of Sullivan, Mahalingam & Kerr (1994, doi:10.1063/1.868274), built on the FixedDomain domain: after each step the in-band Fourier modes — the integer shells lowest_shell to highest_shell, in units of the box's fundamental $2\pi/L$ — are rescaled by a single factor that holds target. The rescale is per-mode, so a divergence-free velocity stays divergence-free.

Prefer VarianceController for a run whose accuracy in time matters, which is nearly always. It holds the same quantity through a rate the scheme integrates and keeps the scheme's order; this one is applied after the step and costs it (see the caveat below). It is kept because it is a published method a reader may need to reproduce, and because holding a band's value exactly is occasionally what is wanted.

Which observable is held follows from the field, chosen to agree with the diagnostics: the kinetic energy $\tfrac{1}{2}\langle\lvert\boldsymbol{u}\rvert^{2}\rangle$ for the velocity (kinetic_energy), the scalar variance $\langle\varphi^{2}\rangle$ for the scalar (scalar_variance) — each the field's $L^{2}$ observable, the $\tfrac{1}{2}$ belonging to the kinetic energy's definition rather than to the field being a vector.

over selects where that target applies, and the two differ in which quantity a run may no longer measure:

  • :band holds the band's own value. The whole-field value then floats, oscillating about its mean as the band feeds the cascade. On the default shells 1–2 — the energy-containing range — most of $k$ is held rather than free, though it remains a measurable.
  • :total rescales the band to absorb the whole-field deficit, so the whole-field value equals target. For the velocity this pins $u'$ and with it the scale of $\mathrm{Re}_\lambda$ (whose value still fluctuates with the instantaneous dissipation). Here $k$ is what the forcing sets and the band is free.

Neither is a default, because the right answer depends on what the run is calibrated against. Simulation in grid mode chooses $\nu$ from the assumed kinetic energy, so a forcing put there by hand must be a :total one or that calibration stops holding. Where nothing calibrates against it, :band is the gentler clamp.

Sizing the rescale reduces the field to a number, so each step blocks on a device-to-host transfer — two under :total, which measures the band and the whole field.

Arguments

  • domain — the FixedDomain the band is built on.
  • target — the value of the held observable, as selected by over.
  • over — :band or :total. Required: a deterministic clamp destroys the physical fluctuation of whatever it holds, and no default is right for every run.
  • lowest_shell = 1, highest_shell = 2 — the rescaled band, as integer shells in units of the box's fundamental $2\pi/L$.
First order in time, and two extremes worth knowing

This is the one forcing that costs the scheme its order, by construction rather than by defect: the rescale is applied after the step, which is Lie–Trotter operator splitting, and Lie–Trotter is first-order however good the scheme is. Measured on the third-order IFLowStorageRK3: 1.02 here, against 3.01 for Linear, ConstantPower, VarianceController and an unforced run. (A stochastic forcing is outside that comparison — it has no classical order to lose.) Molecular dynamics reached the same conclusion about the same manoeuvre — rescaling to fix a quantity each step is the naive thermostat, and the fix is to extend the dynamics with feedback rather than project after the fact.

Two configurations also behave sharply. Under :total, if the out-of-band value alone exceeds target, the band is zeroed — the closest reachable state, and the most violent intervention the rescale can make. At the other end an empty band is left alone rather than divided by ~0, so it stays empty instead of being driven to target. Seed content in the band if a run depends on the clamp taking hold.

Fields

  • band — the band-pass kernel selecting the rescaled shells.
  • target — the held value.
  • over — :band or :total.

Deferred forcing

The operator-free deferred form a strategy's constructor returns, materialized into a concrete forcing once the domain exists.

GBGIsotropicTurbulence.Forcing.DeferredForcing — Type
DeferredForcing

A deferred forcing. The operator-free keyword constructors

Linear(; rate, lowest_shell = 1, highest_shell = 2)
ConstantPower(; injection_rate, lowest_shell = 1, highest_shell = 2)
VarianceRescaling(; target, over, lowest_shell = 1, highest_shell = 2)

each return a DeferredForcing capturing the same keywords, with the same defaults, as their domain-taking forms documented on each strategy; it is materialized into the concrete AbstractForcing once the FixedDomain exists (done for you by Simulation). A forcing argument therefore accepts either a ready-built AbstractForcing (from the domain-taking constructor) or a DeferredForcing.

Examples

The two-form construction is the non-obvious part of this module, so the example lives here; the strategies themselves are built by the forms shown below.

# Name the forcing before any grid exists — the front door supplies the domain:
sim = Simulation(grid_points_per_axis = 64, viscosity = 5e-3,
                 velocity_forcing = ConstantPower(injection_rate = 0.1))

# Or build it directly, once the domain is in hand:
domain = FixedDomain(; grid_points_per_axis = 64)
forcing = ConstantPower(domain; injection_rate = 0.1)

Fields

  • build — the captured constructor closure: calling the DeferredForcing on a FixedDomain invokes it, yielding the concrete strategy.

Forcing methods

The four step methods a strategy may implement (each a no-op by default), listed in the order step! fires them, followed by the trait that declares a strategy supplies a linear rate — part of implementing set_forcing_rate!, since the generator allocates a rate array only where one is declared.

GBGIsotropicTurbulence.Forcing.prepare_forcing! — Function
prepare_forcing!(forcing, field, domain, dt) -> nothing

Update the strategy forcing's internal state once per step, before the Runge–Kutta stages, from the start-of-step field (in spectral representation) and the timestep dt, on the FixedDomain domain. A stateful forcing owns whatever scratch this needs. The default does nothing.

source
GBGIsotropicTurbulence.Forcing.set_forcing_rate! — Function
set_forcing_rate!(forcing, rate, field, domain) -> rate

For a strategy forcing linear in the field, fill the per-mode rate rate — a scalar field in spectral representation holding real values — with $A(\boldsymbol{\kappa})$ (the forcing $f = A \texttt{field}$) and return rate; the scheme folds it into the diffusive integrating factor $\mathcal{E}(\boldsymbol{\kappa})$ (see velocity_integrating_factor), so the forced modes advance at the net linear rate $A(\boldsymbol{\kappa}) - D\lvert\boldsymbol{\kappa}\rvert^{2}$ ($D$ the field's diffusivity). Only a forcing declaring uses_steady_linear_rate is ever handed a rate array, so the default method is never reached in a run; it returns rate untouched. The field is the start-of-step field in spectral representation; domain is the FixedDomain.

source
GBGIsotropicTurbulence.Forcing.add_forcing_source! — Function
add_forcing_source!(forcing, N̂, field, domain, diffusivity) -> N̂

Add the strategy forcing's additive source to the assembled right-hand side N̂, on the FixedDomain domain. The default does nothing.

This is the route a state-dependent forcing must take. It is called at every Runge–Kutta stage and is handed that stage's own field — the velocity $\hat{\boldsymbol{u}}$ or the scalar $\hat{\varphi}$ in spectral representation, whichever this forcing drives — together with the diffusivity acting on it ($\nu$ for the velocity, $\varkappa$ for the scalar). A strategy whose amplitude depends on the current state can therefore measure that state exactly where the scheme will integrate the result.

The alternative costs accuracy: a state-dependent rate frozen once per step is the left-endpoint rectangle rule on $\int A\,\mathrm dt$, dropping the scheme to first order however good it is. Only a steady rate may go through set_forcing_rate!.

Each reduction costs one blocking device-to-host transfer, at every stage — three per stage for VarianceController, one for ConstantPower, where Linear pays none. That is the price of the order this route preserves.

Returns N̂.

The source is accumulated, never assigned

Every stage adds into an N̂ the generator has already filled with the nonlinear term, so an implementation must add its contribution and must not overwrite the buffer.

source
GBGIsotropicTurbulence.Forcing.project_forcing! — Function
project_forcing!(forcing, advanced_field, domain) -> advanced_field

Apply the strategy forcing's post-step projection to advanced_field (a velocity or scalar $\varphi$ field in spectral representation) in place, on the FixedDomain domain. The default does nothing; see VarianceRescaling.

Unlike the two hooks that read the start-of-step field, this one is handed the field the step has already advanced — the argument is named for that instant, since a strategy that rescales toward a target must measure the state it is correcting, not the one it started from.

source
GBGIsotropicTurbulence.Forcing.uses_steady_linear_rate — Function
uses_steady_linear_rate(forcing) -> Bool

Whether forcing drives its field through a per-mode rate that is constant in time, and can therefore be folded into the integrating factor — that is, whether it implements set_forcing_rate!. The default is false; a forcing that does implement the hook must declare it true.

Steady, not merely linear, is the load-bearing word: a per-mode rate re-solved from the state each step must not declare this. Freezing it would be the left-endpoint rectangle rule on $\int A\,\mathrm dt$, dropping the scheme to first order; such a forcing goes through add_forcing_source! instead.

The generator allocates a rate array $A(\boldsymbol{\kappa})$ per field only for a forcing that declares this, so an unforced field, a post-step projection, or a stochastic source carries no rate storage at all. Declaring it is therefore part of implementing set_forcing_rate!: a forcing that fills a rate without declaring one is never given an array to fill, and the ResolvedGenerator constructor rejects it rather than let the forcing go silently unapplied.

SimulationRun

GBGIsotropicTurbulence.SimulationRun — Module
SimulationRun

The run layer:

  • Simulation — the assembled state of a case.
  • advance!, run! — advance one iteration; observe and advance until the callback stops the run (the callback is the observation — the function the loop calls to read the run each iteration — and its return decides continuation).
  • StationarityCriterion, warmup! — the packaged spin-up-to-stationarity observation, and warmup!, the one-line shorthand that runs it.
  • current_time, current_step — the elapsed time and step count.
  • flow_parameters — the run's measured flow state as a Phenomenology FlowParameters.

Read a run's state through sim.state and its deposited observables through sim.cache, with the observables and cache accessors that own them; the run layer adds no forwarding methods of its own.

source

The simulation

The assembled, ready-to-run case — the front-door Simulation(; grid_points_per_axis, viscosity, …) and the domain-taking Simulation(domain; …) constructors. Read its measured state by applying the Observables to sim.state — for example kinetic_energy(sim.state.velocity_spectral) in a run! callback.

GBGIsotropicTurbulence.SimulationRun.Simulation — Type
Simulation(; grid_points_per_axis, κ_max_η = nothing, kinetic_energy = 1.5,
             side_length = 2π, element_type = Float64, array_type = Array,
             dealiasing = TwoThirds(), kwargs...)
Simulation(domain; κ_max_η = nothing, kinetic_energy = 1.5, kwargs...)

A ready-to-run case: the FixedDomain, the IntegratorBuffers, the ResolvedGenerator (the equations of motion, carrying the FlowConditions and the assembly scratch), the chosen scheme, the ResolvedFields state (the velocity $\hat{\boldsymbol{u}}$ and passive scalar $\hat\varphi$ in spectral representation), the ObservablesCache holding what the last iteration deposited, any Tracers, and a clock.

The first form is the front door: from grid_points_per_axis and side_length it builds every piece with sensible defaults, seeds a divergence-free velocity (and, with scalar = true, a mean-zero scalar $\varphi$), and returns a Simulation at $t = 0$. The second takes a FixedDomain you built yourself.

Advance it with advance! / run! / warmup!. Read its measured state by applying the observables to sim.state (e.g. kinetic_energy(sim.state.velocity_spectral)) or through the cache's deposited observables (velocity_physical(sim.cache)); summarize it with flow_parameters, and track its progress with current_time / current_step.

Setting the Reynolds number

By default the run is forced and stationary — a VarianceController drives the whole-field kinetic energy to the value given by the kinetic_energy keyword and holds it there — and the viscosity is chosen from the grid rather than supplied:

Arguments

All keyword except domain (below). The ones marked (front door only) configure the FixedDomain and are consumed by the first form; the rest are forwarded to the Simulation(domain; …) form.

  • grid_points_per_axis — the number of grid points $N$ along each side (front door only); required.
  • domain — a pre-built FixedDomain. This one is positional, not a keyword: it is the argument of the second form, Simulation(domain; …) (the front door builds one for you from grid_points_per_axis, side_length, dealiasing, element_type, array_type).
  • κ_max_η — the resolution criterion $\kappa_{\max}\eta$ used to set $\nu$ in grid mode; $\ge 1.5$ is well-resolved, higher trades Reynolds number for margin. It defaults to nothing and grid mode then uses 2; the sentinel is what lets the constructor tell an omitted keyword from an explicit one, so that giving both it and viscosity is an error rather than a silent drop.
  • viscosity — the kinematic viscosity $\nu$, which is how the Reynolds number is set (it is $1/\nu$ only in units where $u' = L = 1$; measure $\mathrm{Re}_\lambda$ for the run's actual value); omit for grid mode.
  • kinetic_energy = 1.5 — the initial, and when forced the held, kinetic energy $k$; 1.5 gives an r.m.s. velocity $u' = \sqrt{2k/3} = 1$.
  • side_length = 2π — the box side $L$ (front door only).
  • element_type = Float64, array_type = Array — the real element type and storage backend (front door only).
  • dealiasing = TwoThirds() — the DealiasingStrategy ($2/3$ sharp, HouLi smooth, or PhaseShift); it sets $\kappa_{\max}$ and hence the CFL step (front door only).
  • schmidt = 1.0 — the Schmidt number $\mathrm{Sc}$ (scalar diffusivity $\varkappa = \nu/\mathrm{Sc}$). The resolution criterion covers the velocity, not the scalar, whose cutoff at $\mathrm{Sc} > 1$ is the finer Batchelor scale $\eta_B = \eta/\sqrt{\mathrm{Sc}}$ — under-resolved by $\sqrt{\mathrm{Sc}}$ on the same grid, with scalar_dissipation then measuring a truncated field. The package targets $\mathrm{Sc} = O(1)$, with no Batchelor-range machinery. The constructor warns when the run's $\kappa_{\max}\eta_B$ falls below the $1.5$ well-resolved floor — a warning, not an error, so a deliberately under-resolved scalar stays reachable but not silent; the remedy is κ_max_η raised by $\sqrt{\mathrm{Sc}}$, or viscosity set by hand.
  • velocity_forcing, scalar_forcing — an AbstractForcing (or a DeferredForcing from an operator-free constructor); velocity_forcing defaults to a VarianceController driving the whole-field kinetic energy to the value given by the kinetic_energy keyword, and scalar_forcing to NoForcing(). The velocity and scalar are forced independently.
  • scalar = false, scalar_variance = 1.0 — whether to evolve a passive scalar (a mean-zero $\varphi$), and its initial variance.
  • envelope_wavenumber = 2.0 — the large-scale envelope wavenumber $\kappa_p$ of the initial condition, for the velocity and the scalar alike (each shell-summed spectrum peaks at $\kappa_p/\sqrt{2}$); it does not shape the profile when initial_spectrum is given (the model does), but it still sets the integral scale of the assumed state that model is evaluated at.
  • initial_spectrum = nothing — draw the initial velocity from a Phenomenology EnergySpectrum (say VonKarman1948()) instead of the default large-scale Gaussian. A model spectrum needs a flow state, and at $t = 0$ there is nothing measured yet, so one is assumed — a stand-in state, not a measurement of the field about to be seeded, so its integral scale is 1/envelope_wavenumber rather than the $L_{11}$ the seeded field will have: $\varepsilon$ from the Li2008 stationary-dissipation law at the requested kinetic_energy and box side, $u'$ from that same energy, $\nu$ as resolved above, and the integral scale as 1/envelope_wavenumber. The seeded field is then normalized to kinetic_energy, so the model fixes the shape and the assumed state only positions it. This shapes the velocity only; a scalar is always seeded from the default Gaussian envelope, and a scalar-spectrum initial condition is reached by calling random_scalar_spectral! on the built run and announcing the change with fields_modified!.
  • max_dt = Inf — a further ceiling on the adaptive timestep, stated in the run's own time units, and off unless set. It is a third bound, not the only one: the adaptive step is the smallest of the advective rule $\Delta t = C\Delta x / u_{\max}$, a resolution bound $1/(D\kappa_{\min}^{2})$ built from the run's own diffusivity and box, and this. The advective rule alone diverges as a decaying flow approaches rest — past some step the integrating factor annihilates every mode and the clock advances by a number that means nothing — and it is the resolution bound that stops that, needing no constant from the caller. max_dt is for a ceiling only the caller knows, since any default constant would be a claim about the velocity scale they happened to choose.
  • scheme = IFLowStorageRK3(), cfl = recommended_cfl(scheme, domain) — the AbstractIntegrator scheme and its advective-CFL ceiling (adapts to dealiasing).
  • number_of_particles = 0, interpolation_scheme = CatmullRom — the number of Lagrangian Tracers and the spatial scheme that evaluates a field at their positions, forwarded to the Tracers constructor as its interpolation_scheme.
  • trajectory_scheme = EndpointHeun() — the scheme that advances the trajectories in time, an AbstractParticleIntegrator; its registers — the per-step scratch that scheme needs, meaningless to read between calls — are allocated for you. Pass AdamsBashforth() when trajectory accuracy in time limits a measurement: it costs one stored array per extra order and saves an interpolation per step.
  • rng — the random stream for the initial condition and the tracer seeding (defaults to Random.default_rng()).
The default drives the kinetic energy to a set value, so read it as a control target

VarianceController restores $k$ exponentially to kinetic_energy, pinning $u'$ and the scale of $\mathrm{Re}_\lambda$. It does not impose the value step by step as a rescale does, so the fluctuation it leaves is genuine — but it is a controlled variable's fluctuation, with the gain setting its amplitude. For the free fluctuation of $k$, force with fixed injection (ConstantPower) instead.

  • Grid mode (no viscosity): the constructor picks the highest Reynolds number consistent with the resolution criterion κ_max_η, in two steps.

    First it estimates the dissipation the box sustains, from the box-normalized law Li2008 (in Phenomenology.Scalings): $\varepsilon = (k/G)^{3/2}/L$, with kinetic_energy the energy $k$, side_length the side $L$, and $G \approx 0.9$ a dimensionless constant. $G$ carries $C_\varepsilon^{-2/3}$ and the ratio $L_{11}/L$, and that ratio is set by where a run is forced — so the estimate assumes forcing in the same low shells as the runs it was calibrated on, and a forcing moved higher invalidates it.

    Then it sets $\nu$ so that $\kappa_{\max}\eta$ equals κ_max_η, with $\kappa_{\max}$ the max_wavenumber and $\eta$ the Kolmogorov microscale. Since $\kappa_{\max}\eta = f\pi\eta/\Delta x$ with $f$ the retained-Nyquist fraction, κ_max_η = 2 gives $\Delta x \approx \eta$ under the default $2/3$ rule.

    The criterion is not equally strict across dealiasing strategies

    It treats the whole retained band as clean signal — exact for TwoThirds and PhaseShift, approximate for HouLi, whose top of band is damped rather than dealiased. The gap is not cosmetic: $f = 1$ puts $\eta \approx 0.64\Delta x$ at κ_max_η = 2 against $0.96\Delta x$ for $2/3$, and since $\nu \propto f^{-4/3}$ that hands HouLi a $\mathrm{Re}_\lambda$ about 31% higher on the same grid. Raise κ_max_η when comparing across strategies.

    The grid and κ_max_η together fix $\mathrm{Re}_\lambda \sim N^{2/3}$; kinetic_energy and side_length fix the units. The chosen $\nu$, $\varepsilon$ and $\mathrm{Re}_\lambda$ are logged.

    One precondition: the choice is self-consistent only if the run holds $k$ near kinetic_energy. The default VarianceController does, to the tolerance its gain sets — its restoring term measures the whole-field $k$, which is the quantity assumed here. Give the velocity a forcing that lets $k$ float, or one holding some other quantity (a VarianceRescaling(over = :band) holds the band instead), and the $\nu$ chosen here no longer matches the run.

  • Explicit mode: pass viscosity and it is used directly; the two are alternatives, and passing both raises an ArgumentError rather than dropping one — for a decaying run (velocity_forcing = NoForcing()) or manual control. Grid mode is calibrated on a stationary forced balance (Li2008's $G$ is fitted to forced-isotropic DNS), so a decaying run should set $\nu$ explicitly: the resolution it buys is only meaningful while the box sustains the energy the law assumes.

Examples

The two ways in, and the two ways to set the Reynolds number:

# Grid mode — a 128³ forced-stationary run, ν set from the resolution criterion:
sim = Simulation(grid_points_per_axis = 128)

# Explicit mode — set ν directly, carry a passive scalar, force at constant power:
sim = Simulation(grid_points_per_axis = 128, viscosity = 1e-2;
                 scalar = true, velocity_forcing = ConstantPower(injection_rate = 0.1))

# Domain-first — build the frame yourself, then hand it to the second form:
domain = FixedDomain(; grid_points_per_axis = 128, side_length = 2π, dealiasing = HouLi(),
                     element_type = Float64, array_type = Array)
sim = Simulation(domain; viscosity = 1e-2)

Fields

Three of these are what a user reads — state, cache, and tracers. The rest are the machinery the step runs on: they hold partial values while a step is in flight, so read them only between steps, and treat their contents as the scheme's business rather than the run's state.

  • state — the ResolvedFields (the evolving û, φ̂).
  • cache — the ObservablesCache: the observables the iteration deposits at its end.
  • domain, buffers, generator, scheme — the FixedDomain, IntegratorBuffers, the ResolvedGenerator (whose conditions field is the run's FlowConditions), and the chosen scheme.
  • tracers, trajectory_scheme, particle_buffers — the Tracers being advected along with the fields, the scheme advancing them along their trajectories, and that scheme's registers. All nothing when the run carries no tracers.
  • cfl, clock — the advective-CFL coefficient, and the time/step counter.

Advancing the run

Advance one iteration, or observe-and-advance until the callback stops the run; the packaged stationarity observation and its one-line shorthand spin a fresh run up to measurement readiness.

GBGIsotropicTurbulence.SimulationRun.advance! — Function
advance!(sim; dt = nothing)

Advance sim by one timestep in place and return it. Pass dt to force a fixed step; with dt = nothing the step is adaptive — the smallest of the advective-CFL value for the current velocity, the resolution bound the box and its diffusivity impose, and max_dt.

Closes the iteration with deposit!, so the cache is readable when it returns. Advects the tracers, if any, by Heun-in-time on the start- and end-of-step velocities, and updates the clock.

Returns sim.

GBGIsotropicTurbulence.SimulationRun.run! — Function
run!(callback, sim)
run!(sim) do sim … end

Observe and advance sim until the observation stops it, and return it. After every iteration — and once at the seeded initial state, before any advance — the callback observes the run as callback(sim): it reads the state and the cached observables, records what it wants, and returns true to continue or false to stop (any other return throws an ArgumentError — the decision may not be left implicit). Only then does the next iteration run: the timestep from the cached maximum speed, the step, the tracer advance, and the closing deposits. A run of $n$ iterations therefore observes $n + 1$ instants — the first before any step, the last after the final one, with statistics recorded before the stop.

Stopping is the observation's decision on observables, never a run option: a fixed-length run is a callback that accumulates elapsed turnovers and stops at a chosen total. A span of simulation time compares current_time against a target; a step budget compares current_step; an eddy-turnover budget accumulates $\Delta t \varepsilon/k$ from the observables it computes; spin-up to stationarity is the packaged StationarityCriterion. Whatever the callback needs beyond the cached observables it computes itself, at its own cadence, with the exported reductions and recoveries.

Examples

run!(sim) do s
    current_time(s) < 5.0                        # a span of simulation time
end

history = Float64[]                              # record k every iteration; stop at 200 steps
run!(sim) do s
    push!(history, kinetic_energy(s.state.velocity_spectral))
    current_step(s) < 200
end

run!(StationarityCriterion(), sim)               # spin up to statistical stationarity

Returns sim.

GBGIsotropicTurbulence.SimulationRun.StationarityCriterion — Type
StationarityCriterion(; gate_scalar = true, gate_skewness = true, min_turnovers = 5,
                        window_turnovers = 4, tol = 0.05, skew_floor = 0.1,
                        max_turnovers = 60)

The packaged spin-up observation for run!: a callback that watches the run settle into statistical stationarity and stops it there — run!(StationarityCriterion(), sim) is the detecting spin-up, and warmup! is the one-line shorthand for exactly that call. Use it before measurement on any freshly seeded forced run. A freely decaying run (NoForcing()) has no stationary state to detect — its $\varepsilon$ never plateaus — so the criterion can only run to max_turnovers and warn; give a decaying run a fixed-length loop instead, which is a three-line callback (see run!).

At each iteration it measures the dissipation $\varepsilon$ — the small scales settle last, so a flat $\varepsilon$ is the strict indicator, where a constant-energy forcing clamps $k$ flat and a fixed-injection forcing makes it ring, which is why $k$ is kept out of the gate — and the kinetic energy $k$, which normalizes the eddy-turnover clock $\Delta t \varepsilon/k$ it accumulates, and tests flatness over a trailing window; it stops the run when every gate holds, or gives up with a warning at max_turnovers.

Arguments

All keyword:

  • gate_scalar — when the run's scalar is forced, also require the scalar variance $\langle\varphi^2\rangle$ to be flat (the scalar settles after the velocity; an unforced scalar has no stationary state and is never gated).
  • gate_skewness — also require the velocity-derivative skewness to have plateaued and reached $\lvert S\rvert \ge \texttt{skew\_floor}$ — the decisive "real turbulence yet" signal: a random-phase field starts at $S \approx 0$ and only a developed cascade reaches $S \approx -0.5$. The skewness costs transforms, so it is measured on the criterion's own sampling interval — one sample per window_turnovers / 40 of turnover time, giving about forty samples across the trailing window — rather than every iteration.
  • min_turnovers, window_turnovers, tol — do not test before min_turnovers eddy-turnover times (past the start-up overshoot); flatness is a two-half-window mean comparison over the trailing window_turnovers, relative drift below tol.
  • skew_floor — the minimum $\lvert S\rvert$ for a plateau to count as developed turbulence. The default 0.1 is a floor against a random-phase field, which starts at $S \approx 0$; it is a fifth of the $\lvert S\rvert \approx 0.5$ of a developed cascade, so clearing it means "no longer Gaussian", not "fully developed". Raise it toward 0.4 when the run's statistics depend on the cascade being mature.
  • max_turnovers — the give-up cap: reaching it stops the run with a warning rather than spinning forever.

The criterion carries its own observation state (the sampled signals and the turnover clock), so build a fresh one per run.

Fields

The fields are not the keywords: gate_skew, min_turnovers, window_turnovers, tol and skew_floor all live inside monitor, which holds the sampled series together with the thresholds that judge them. Build one through the keyword constructor above.

  • monitor — the sampled signals (the turnover clock, $\varepsilon$, the scalar variance, the skewness — not $k$, which this criterion deliberately never gates on) and the gate settings and tolerances that test them.
  • max_turnovers — the give-up cap.
  • gate_scalar — the requested scalar gate (applied only when the run's scalar is forced).
  • elapsed_turn, last_time, started — the turnover clock's state.

GBGIsotropicTurbulence.SimulationRun.warmup! — Function
warmup!(sim; kwargs...)

A one-line shorthand, and nothing more: warmup!(sim; kwargs...) is exactly

run!(StationarityCriterion(; kwargs...), sim)

— it spins sim up to a statistically stationary state before measurement and returns it, by running the observation-first loop with the packaged stationarity observation. Every keyword is passed through to StationarityCriterion untouched; its docstring is the home for what is detected (the flat dissipation, the scalar-variance and derivative-skewness gates, the give-up cap) and for every option. For a fixed spin-up budget, write the three-line budget callback instead (see run!).

Examples

warmup!(sim)                          # detect stationarity (ε- and skewness-plateau gates)
warmup!(sim; gate_skewness = false)   # relax the skewness gate (a shorter, looser spin-up)

Returns sim.

GBGIsotropicTurbulence.SimulationRun.current_step — Function
current_step(sim)

The number of steps sim has taken — how far the run has gone.

Distinct from the observables cache's epoch, which counts changes to the state rather than advances of the run: a completed step advances the epoch, but so does any announced out-of-band mutation. The constructor's seeding deposit already leaves the fields epoch at 1, so after two steps and one announced mutation the clock reads step 2 and the fields epoch reads 4. Use this to ask how far the run has gone, and the epoch to ask whether a cached value is still the right one.

Flow parameters

Bridge the run's measured state to a Phenomenology FlowParameters, so any reference law can be evaluated at the run's measured state.

GBGIsotropicTurbulence.SimulationRun.flow_parameters — Function
flow_parameters(sim)

The measured flow state of sim as a FlowParameters — the bridge that lets any Phenomenology reference law be evaluated at the run's measured state. The viscosity $\nu$ and the Schmidt number are read from the generator's conditions; the dissipation $\varepsilon$, the r.m.s. velocity $u' = \sqrt{2k/3}$ (from the kinetic energy $k$), the longitudinal integral scale $L_{11}$, and — when the run carries a scalar — the scalar dissipation $\varepsilon_\varphi$ are measured from the current state (the scalar dissipation is left NaN only for a scalar-free run, where the scalar reference laws do not apply).

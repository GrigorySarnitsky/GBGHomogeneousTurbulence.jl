Cache

GBGIsotropicTurbulence.Cache — Module
Cache

The observables cache — the stamped storage where the iteration leaves the observables it produces, for the run's own components and any observation to read. An iteration is one advance of the run — one step! and the deposit! that closes it; between iterations the run stands at one $t_n$, after one advance and before the next — an instant of the run's clock, not a face of the periodic box; a slot's stamp records which of these instants its value belongs to, so a read can be refused rather than served stale. The cache's operations:

  • ObservablesCache — the cache itself: the slots, their stamps, and the epoch counters.
  • fields_modified!, particles_modified! — announce a state or tracer mutation made outside the iteration, so the affected stamps go stale and reads throw until the next deposit.
  • velocity_physical, vorticity_physical, scalar_physical — the checked reads of the cached fields (the velocity, vorticity, and scalar in physical representation).
  • max_speed — the cached maximum velocity component, the number the timestep choice reads (one generic with the field reduction in Observables, whose docstring is the home).
  • particle_velocities — the checked read of the particle velocities $\boldsymbol{u}(t_n, \boldsymbol{X}(t_n))$, the velocity sampled along each trajectory.

The solver's side of the contract is deposit! — homed in Propagator, with the iteration it closes — which fills and stamps every slot at the iteration's end; internal per-slot deposit and take verbs move the individual stamps. A caller reads through the accessors and never deposits.

The observables cache

The stamped storage the iteration fills at its end with its observables — every read serves the deposited value or throws, and nothing is ever recomputed on a read.

GBGIsotropicTurbulence.Cache.ObservablesCache — Type
ObservablesCache(domain; scalar = false, particle_velocities = nothing)

The observables cache of a run — the stamped storage where each iteration deposits, at its end, the observables its own schedule produces: the velocity $\boldsymbol{u}$ and vorticity $\boldsymbol{\omega}$ in physical representation, the scalar $\varphi$ in physical representation when the run carries one, the maximum velocity component (the max_speed number the next timestep choice reads), and — when the run advects tracers — the particle velocities $\boldsymbol{u}(t_n, \boldsymbol{X}(t_n))$. The contents are automatic — derived from the configuration, never declared: the cache holds exactly what the iteration computes, materializes, and leaves alive at the iteration's end, and nothing may be added on any cost axis.

Build it on a FixedDomain domain; pass scalar = true when the run evolves a passive scalar (it adds the scalar's slot), and particle_velocities — the tracer set's own point-value storage — when the run advects tracers (the slot IS that storage, stamped here; the tracers' push writes it). The Simulation front door — the build-everything convenience constructor — builds, wires, and seeds one for you.

Read through the accessors — velocity_physical, vorticity_physical, scalar_physical, and max_speed — each of which returns the deposited value or throws. Nothing in the cache is ever recomputed: a read that finds a stale, taken, or never-deposited slot reports a scheduling error — it throws an ErrorException whose message names the slot and which of the three states it is in — and the only repair is to fix the schedule that failed to deposit.

Note

A slot is also its producer's register: between deposits the step works in the same array, so a cached field is only valid between iterations. Treat every returned array as read-only — it is the storage the next iteration will work in.

Fields

  • velocity, vorticity — the cached velocity and vorticity in physical representation (the arrays double as the step's stage recovery registers).
  • scalar — the cached scalar in physical representation, or nothing for a scalar-free run.
  • velocity_epoch, vorticity_epoch, scalar_epoch, max_speed_epoch — each slot's stamp: the fields epoch it was deposited at, or a sentinel (never deposited / in use as scratch).
  • max_speed — the cached maximum velocity component (a host number).
  • particle_velocities — the particle-velocities slot (the tracer set's own point-value storage, whose (M, 3) array the accessor extracts with point_values), or nothing for a tracer-free run; sample_fields_epoch / sample_particles_epoch are its stamps against BOTH epochs, since the sample is a function of the state and the positions together.
  • fields_epoch — the state's epoch: advanced by every completed step and by fields_modified!; a stamp is current exactly when it equals this.
  • particles_epoch — the tracer positions' epoch (advanced by the tracer push), the second freshness axis of the trajectory-bound slots.

GBGIsotropicTurbulence.Cache.fields_modified! — Function
fields_modified!(cache)

Announce that the resolved fields — $\hat{\boldsymbol{u}}$ and $\hat\varphi$, in spectral representation — were changed outside the iteration (a re-seeded velocity, any direct write to the state's storage). Advances the fields epoch of cache, so every cached observable is stale and reads throw until the next deposit; that interval belongs to whoever made the change. Returns cache.

The sanctioned mutators call this for you: step! advances the epoch itself when it completes, and the iteration's closing deposit then restores the cache. After a hand-made mutation, re-deposit with the run layer's deposit! before advancing again — the timestep choice reads the cached maximum speed.

source
GBGIsotropicTurbulence.Cache.particles_modified! — Function
particles_modified!(cache)

Announce that the tracer positions were changed outside the iteration (a reseed, a hand-written correction, any direct write to the tracer storage) — the particle counterpart of fields_modified!. Advances the particles epoch of cache, so every trajectory-bound observable is stale and reads throw until the next deposit. Returns cache.

The sanctioned mutator calls it for you: the run layer's tracer push announces its own advance, and the closing deposit then re-stamps the sample. A hand-run loop that repositions tracers itself must call this, then re-record the trajectory sample before advancing.

The checked reads

Each accessor returns the observable deposited at the current epoch, or throws; the cached maximum speed is read through max_speed, documented with the reduction it stores.

GBGIsotropicTurbulence.Cache.velocity_physical — Function
velocity_physical(cache)

The velocity $\boldsymbol{u}$ in physical representation at the current epoch — the checked read of the ObservablesCache cache's velocity slot. Returns the deposited field when its stamp is current, and throws otherwise (the slot is mid-iteration scratch, stale, or was never deposited): the throw is an ErrorException naming the slot and which of the three states it is in, and nothing is ever recomputed on a read. Treat the returned field as read-only — it is the storage the next iteration works in.

source
GBGIsotropicTurbulence.Cache.vorticity_physical — Function
vorticity_physical(cache)

The vorticity $\boldsymbol{\omega} = \nabla\times\boldsymbol{u}$ in physical representation at the current epoch — the checked read of the ObservablesCache cache's vorticity slot, with exactly velocity_physical's contract (the deposited field or a throw; never a recomputation; read-only). The deposited value is produced by vorticity_physical! — measure with that function, read with this one.

source
GBGIsotropicTurbulence.Cache.scalar_physical — Function
scalar_physical(cache)

The scalar $\varphi$ in physical representation at the current epoch — the checked read of the ObservablesCache cache's scalar slot, with exactly velocity_physical's contract (the deposited field or a throw; never a recomputation; read-only). Throws an ArgumentError when the run carries no scalar.

source
GBGIsotropicTurbulence.Cache.particle_velocities — Function
particle_velocities(cache)

The particle velocities $\boldsymbol{u}(t_n, \boldsymbol{X}(t_n))$ at the current epoch — the $(M, 3)$ array of the flow velocity sampled at the position each tracer occupies at that instant: the genuine Lagrangian velocity the statistics accumulate. The checked read of the ObservablesCache cache's particle-velocities slot: it serves the deposited values or throws, like every cached read — the sample depends on the state and the positions, so it is current only when both epochs match its stamps. Throws an ArgumentError when the run advects no tracers.

Note

This is never the second velocity of the tracer position update (the corrector stage of the predictor–corrector push, advect!): that one is evaluated at a predicted position no tracer ever occupies — a stage register of the scheme, not a sample of the flow — and it is not readable.

GBGIsotropicTurbulence.Particles — Module
Particles

Lagrangian tracer tracking:

  • Tracers — the tracer set (positions and a selectable interpolation scheme).
  • record_trajectory_velocity! — put the start-of-step Lagrangian velocity on record.
  • advect! — the second-order tracer push (Heun-in-time on the start- and end-of-step velocity).
  • sample! — read a field along the trajectories; velocity_buffer / scalar_buffer allocate its out buffers.
  • tracer_positions, tracer_velocities, number_of_tracers — the trajectory readouts.

The tracer set

Tracer positions plus a selectable interpolation scheme, preallocated for allocation-free advection, with the accessors that read a tracer set's state — its positions, most-recent trajectory velocities, and count.

GBGIsotropicTurbulence.Particles.Tracers — Type
Tracers(domain, number_of_tracers; scheme, rng = default_rng())
Tracers(domain, positions; scheme)

A set of Lagrangian tracers, built on domain's backend and element type. The first form seeds number_of_tracers tracers uniformly at random in the periodic box of domain; the second wraps a given (M, 3) array of M tracer positions (the three columns are the $x, y, z$ components), converting it to domain's backend and element type. The scheme is the GBGPeriodicFields velocity-interpolation scheme used to evaluate the velocity (and any sampled field) at the tracer positions. CatmullRom is the $C^1$ choice (the Simulation front door's default tracer_scheme); LalescuSpline(n, m) and LagrangeSpline(n) offer higher smoothness or interpolation order — at a wider stencil, useful for derivative-sensitive readouts such as acceleration statistics — with n (and, for LalescuSpline, m) the stencil and smoothness parameters. The rng (first form only) is the random stream seeding the uniformly-random tracer positions; it defaults to Random.default_rng().

Read the tracer state with tracer_positions, tracer_velocities, and number_of_tracers; the remaining fields are preallocated predictor and point-value scratch, so the tracer push allocates no per-step memory.

Fields

  • positions — the (M, 3) tracer positions (read with tracer_positions).
  • predictor — (M, 3) scratch for the Heun predictor.
  • position_points, predictor_points — PointSets wrapping positions / predictor for interpolation.
  • velocity1, velocity2 — the interpolated velocities at the start-of-step and predictor positions; velocity1 is the retained trajectory velocity (read with tracer_velocities).
  • scheme — the velocity-interpolation scheme.

GBGIsotropicTurbulence.Particles.tracer_velocities — Function
tracer_velocities(tracers)

The (M, 3) array of the most recent trajectory velocities $\boldsymbol{u}(t_n, \boldsymbol{X})$ — the velocity at the positions the tracers occupy, at the instant they occupy them, put on record by record_trajectory_velocity! before the step. This is the Lagrangian velocity the statistics accumulate.

Note

Not the second velocity of the Heun pair. That one is evaluated at the predicted position, which the tracer never reaches, so it is a stage value of the integration scheme rather than a sample of the flow along the trajectory, and it is not read back.

The tracking loop

The steps of Lagrangian tracking: put the start-of-step velocity on record along the trajectories, advance the tracers with second-order Heun-in-time advection once the fields have moved, then read a physical field along their trajectories — all feeding the Lagrangian statistics. The push is two verbs because the run holds a single physical velocity field, so the start-of-step values are taken off it before the state advances.

GBGIsotropicTurbulence.Particles.record_trajectory_velocity! — Function
record_trajectory_velocity!(tracers, u) -> tracers

Record the Lagrangian velocity $\boldsymbol{u}(t_n, \boldsymbol{X})$ — the flow velocity seen by each tracer where it currently sits — by interpolating the physical velocity field u $\boldsymbol{u}$ onto the tracer positions with the set's interpolation scheme.

Call it on the start-of-step velocity, before the field solver advances the state; advect! then completes the push from the recorded values and the end-of-step field. The push is split across these two verbs because a run holds only one physical velocity field: the observation cache recomputes that chart in place once the state has advanced, so the start-of-step values must be taken off it while it still holds $\boldsymbol{u}(t_n)$. Recording them costs $M \times 3$ values for $M$ tracers, where keeping the field itself would cost $N^{3} \times 3$.

What is recorded is also the trajectory velocity read back by tracer_velocities, and the quantity the Lagrangian statistics accumulate.

GBGIsotropicTurbulence.Particles.advect! — Function
advect!(tracers, velocity_end, domain, dt) -> tracers

Advance the tracer positions by one step of size dt, in place, by Heun-in-time on the velocity at the two ends of the step — the start-of-step values that record_trajectory_velocity! put on record, and the end-of-step physical velocity field velocity_end $= \boldsymbol{u}(t_{n+1})$:

\[\begin{aligned} \boldsymbol{v}_1 &= \boldsymbol{u}(t_n, \boldsymbol{X}), & \boldsymbol{X}^{*} &= \boldsymbol{X} + \Delta t \boldsymbol{v}_1, \\ \boldsymbol{v}_2 &= \boldsymbol{u}(t_{n+1}, \boldsymbol{X}^{*}), & \boldsymbol{X} &\leftarrow \boldsymbol{X} + \tfrac{\Delta t}{2}(\boldsymbol{v}_1 + \boldsymbol{v}_2), \end{aligned}\]

with positions wrapped into $[0, L)$, where the box side $L$ is read from domain (a FixedDomain). This is second-order accurate in time — advecting on the frozen start-of-step velocity alone would be first order.

Note

$\boldsymbol{v}_1$ is read from the tracer set, not recomputed here, so record_trajectory_velocity! must already have run against $\boldsymbol{u}(t_n)$ for this step. Calling advect! twice without re-recording pushes the second step off a stale $\boldsymbol{v}_1$.

sample!(out, field, tracers) -> out

Sample the physical field at the current tracer positions into the point-value buffer out (a VectorPointValues for the velocity, a ScalarPointValues for the scalar $\varphi$), using the tracers' interpolation scheme.

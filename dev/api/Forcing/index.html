Forcing

GBGIsotropicTurbulence.Forcing — Module
Forcing

The interchangeable energy-injection strategies:

  • AbstractForcing — the strategy supertype, defining the four-hook lifecycle below.

A strategy acts on the step through up to four methods, each defaulting to doing nothing, listed in the order the step calls them:

  • prepare_forcing! — advance the forcing's own internal state, once per step.
  • set_forcing_rate! — supply a linear forcing rate to be folded into the integrating factor; uses_linear_rate declares that a forcing supplies one.
  • add_forcing_source! — add a source term at each stage.
  • apply_forcing! — project or rescale the field after the step.

A fifth name is not a hook: DeferredForcing is the operator-free keyword form of a strategy, materialized once the Simulation has built the domain. It exists at construction time and the step never calls it.

The strategies are NoForcing, BandRescaling, Linear and ConstantPower, one implementation serving both the velocity and the scalar through tensor-order-generic field operators.

Which keywords carry defaults follows one test: does the value come from the method, or from this run? A strategy's canonical band — lowest_shell = 1, highest_shell = 2, the large-scale band of homogeneous isotropic turbulence — is a property of the method and defaults. What a run holds fixed — target, rate, and BandRescaling's over — has no canonical value and is therefore required. So a default here never hides a choice you needed to make. The two fields are forced independently: FlowConditions takes a separate velocity_forcing and scalar_forcing, so a run can force one, both, or neither.

Forcing strategies

The forcing supertype and its concrete strategies: the unforced baseline, deterministic band rescaling, and the two linear-rate forcings. One implementation serves either the velocity or the scalar.

GBGIsotropicTurbulence.Forcing.AbstractForcing — Type
AbstractForcing

Supertype of the energy-injection strategies. A strategy may implement any of prepare_forcing! (advance the strategy's own internal state — a stochastic forcing's random process, say — never the simulation state), set_forcing_rate! (a linear forcing rate folded into the integrating factor — a strategy implementing it must also declare uses_linear_rate, or it is never given a rate array to fill), add_forcing_source! (an additive per-stage source), and apply_forcing! (a post-step projection); all default to doing nothing, and a strategy owns whatever scratch its hooks need.

Three of the four hooks mutate and return their second argument; prepare_forcing! is the exception — its field is read-only and what it advances is the forcing's own internal state, so it returns nothing.

The hooks form one per-step lifecycle with a fixed order: prepare_forcing! and set_forcing_rate! run once before the Runge–Kutta stages (whatever internal state a later hook consumes must be prepared here), add_forcing_source! runs at every stage, and apply_forcing! runs after the completed step. The linear rate and the additive source are two channels of one forcing term — the part linear in the field is folded exactly into the integrating factor, the remainder is added at the stages — so a single strategy may legitimately use both.

Each mutating hook returns its mutated argument (set_forcing_rate! the rate, add_forcing_source! the right-hand side, apply_forcing! the field); prepare_forcing! returns nothing.

One instance per forced field, for a strategy that carries state

A strategy holding per-field scratch or a random stream must not drive both fields from one instance, or their bookkeeping is conflated; FlowConditions throws an ArgumentError rather than let that happen. A stateless strategy — one whose whole content is its band and its target — has nothing to conflate and may be shared.

GBGIsotropicTurbulence.Forcing.BandRescaling — Type
BandRescaling(domain; target, over, lowest_shell = 1, highest_shell = 2)

Deterministic rescaling forcing (post-step) that holds a field's amplitude fixed, built on the FixedDomain domain. Each step the in-band Fourier modes — the integer shells lowest_shell to highest_shell, in units of the box's fundamental $2\pi/L$ — are rescaled by a single factor to hold the target.

The target is a number: the value the held observable is to keep. Which observable that is follows from the field, chosen to agree with the diagnostics — the kinetic energy $\tfrac{1}{2}\langle\lvert\boldsymbol{u}\rvert^{2}\rangle$ (kinetic_energy) for the velocity, the scalar variance $\langle\varphi^{2}\rangle$ (scalar_variance) for the scalar — the field's $L^{2}$ observable, carrying the $\tfrac{1}{2}$ only for the vector.

The over keyword selects where the target applies. It is required: a deterministic clamp destroys the physical fluctuation of whatever it holds, so this choice decides which quantity your run may no longer measure, and there is no answer that is right for every run.

  • :band — hold the band's own value; the whole-field value then floats, oscillating slowly about its mean as the band feeds the cascade. The band's energy is then an artifact of the forcing, while $k$ remains a measurable of the flow.
  • :total — rescale the band to absorb the whole-field deficit so the whole-field value equals target (for the velocity this pins the r.m.s. velocity $u'$, setting the scale of $\mathrm{Re}_\lambda$ — its value still fluctuates with the instantaneous dissipation). If the out-of-band value alone exceeds target, the band is zeroed — the closest reachable state — and the most violent intervention the rescale can make, not the absence of one: it empties the energy-containing range in a single step, so $L_{11}$, $u'$ and $\mathrm{Re}_\lambda$ are meaningless for turnovers afterwards. Here $k$ is the artifact and the band is free.
Which one a run wants depends on what else reads ``k``

The Simulation front door passes :total, and not as a preference: in grid mode it chooses $\nu$ from the assumed kinetic energy, through the box-normalized dissipation law, so the resolution criterion $\kappa_{\max}\eta$ is only self-consistent if the run really holds $k$ there — which is exactly what :total guarantees. A hand-built forcing that nothing downstream calibrates against has no such constraint, and :band is then the gentler clamp.

Rescaling preserves the divergence-free constraint either way.

Note

This is a deterministic clamp, not a faithful stationary sampler. Holding an amplitude fixed by deterministic rescaling is the Berendsen-thermostat limit of stochastic velocity rescaling: it has no conserved quantity, is not associated with a well-defined ensemble except in limiting cases, and suppresses the physical fluctuations of the quantity it holds (Bussi, Donadio & Parrinello 2007 — Canonical sampling through velocity rescaling, J. Chem. Phys. 126, 014101, doi:10.1063/1.2408420). Use it to spin up or to pin an amplitude; when the held quantity is itself measured, prefer a fixed-injection forcing (ConstantPower), which leaves the energy free to fluctuate.

GBGIsotropicTurbulence.Forcing.Linear — Type
Linear(domain; rate, lowest_shell = 1, highest_shell = 2)

Linear (negative-damping) forcing $f = A \texttt{field}$ in a low-wavenumber band — the fixed-rate member of the two linear forcings, with ConstantPower the member whose rate is re-solved each step (a band-limited variant of Lundgren 2003 — CTR Annual Research Briefs, which carries no DOI — whose linear forcing acts at every wavenumber), built on the FixedDomain domain, with the fixed rate $A = \texttt{rate}$ on the integer shells lowest_shell to highest_shell, in units of the box's fundamental $2\pi/L$. The rate is folded into the integrating factor (exact for the linear term), so the forced band modes grow at net rate $A - D\lvert\boldsymbol{\kappa}\rvert^{2}$ ($D$ the field's diffusivity). A positive rate amplifies the field.

GBGIsotropicTurbulence.Forcing.ConstantPower — Type
ConstantPower(domain; target, lowest_shell = 1, highest_shell = 2)

Constant-injection-rate forcing, built on the FixedDomain domain: a banded linear forcing $f = A \texttt{field}$ on the integer shells lowest_shell to highest_shell (in units of the box's fundamental $2\pi/L$; default 1–2), whose rate $A$ is set each step so the field's injection rate holds the target. A linear rate injects at $2 A E_{\mathrm{band}}$, with $E_{\mathrm{band}}$ the band's own observable, so the rate that holds the target is

\[A = \frac{\texttt{target}}{2 E_{\mathrm{band}}}.\]

In stationarity the injection balances dissipation, so target is a number: the value of the dissipation rate to hold, chosen to agree with the diagnostics — the rate $\varepsilon$ for the velocity (measured by dissipation) and $\varepsilon_\varphi$ for the scalar (by scalar_dissipation ). Note what kind of quantity that is: here the held observable is a rate, where BandRescaling holds an amplitude. The rate is folded into the integrating factor; like Linear, it preserves a solenoidal velocity.

Deferred forcing

The operator-free deferred form a strategy's constructor returns, materialized into a concrete forcing once the domain exists.

GBGIsotropicTurbulence.Forcing.DeferredForcing — Type
DeferredForcing

A deferred forcing. The operator-free keyword constructors

Linear(; rate, lowest_shell = 1, highest_shell = 2)
ConstantPower(; target, lowest_shell = 1, highest_shell = 2)
BandRescaling(; target, over, lowest_shell = 1, highest_shell = 2)

each return a DeferredForcing capturing the same keywords, with the same defaults, as their domain-taking forms documented on each strategy; it is materialized into the concrete AbstractForcing once the FixedDomain exists (done for you by Simulation ). A forcing argument therefore accepts either a ready-built AbstractForcing (from the domain-taking constructor) or a DeferredForcing.

Fields

  • build — the captured constructor closure: calling the DeferredForcing on a FixedDomain invokes it, yielding the concrete strategy.

Forcing methods

The four step methods a strategy may implement (each a no-op by default), listed in the order step! fires them, followed by the trait that declares a strategy supplies a linear rate — part of implementing set_forcing_rate!, since the generator allocates a rate array only where one is declared.

GBGIsotropicTurbulence.Forcing.prepare_forcing! — Function
prepare_forcing!(forcing, field, domain, dt) -> nothing

Update the strategy forcing's internal state once per step, before the Runge–Kutta stages, from the start-of-step field (in spectral representation) and the timestep dt, on the FixedDomain domain. A stateful forcing owns whatever scratch this needs. The default does nothing.

source
GBGIsotropicTurbulence.Forcing.set_forcing_rate! — Function
set_forcing_rate!(forcing, rate, field, domain) -> rate

For a strategy forcing linear in the field, fill the per-mode rate rate — a scalar field in spectral representation holding real values — with $A(\boldsymbol{\kappa})$ (the forcing $f = A \texttt{field}$) and return rate; the scheme folds it into the diffusive integrating factor $\mathcal{E}(\boldsymbol{\kappa})$ (see velocity_integrating_factor), so the forced modes advance at the net linear rate $A(\boldsymbol{\kappa}) - D\lvert\boldsymbol{\kappa}\rvert^{2}$ ($D$ the field's diffusivity). Only a forcing declaring uses_linear_rate is ever handed a rate array, so the default method is never reached in a run; it returns rate untouched. The field is the start-of-step field in spectral representation; domain is the FixedDomain.

source
GBGIsotropicTurbulence.Forcing.add_forcing_source! — Function
add_forcing_source!(forcing, nonlinear, domain) -> nonlinear

Add the strategy forcing's additive source to the dealiased nonlinear-term buffer nonlinear at each Runge–Kutta stage (the source is held fixed over the step, so it integrates at the scheme's order), on the FixedDomain domain. The default does nothing.

source
GBGIsotropicTurbulence.Forcing.apply_forcing! — Function
apply_forcing!(forcing, field, domain) -> field

Apply the strategy forcing's post-step projection to field (a velocity or scalar $\varphi$ field in spectral representation) in place, on the FixedDomain domain. The default does nothing; see BandRescaling.

source
GBGIsotropicTurbulence.Forcing.uses_linear_rate — Function
uses_linear_rate(forcing) -> Bool

Whether forcing drives its field through a linear per-mode rate — that is, whether it implements set_forcing_rate!. The default is false; a forcing that does implement the hook must declare it true.

The generator allocates a rate array $A(\boldsymbol{\kappa})$ per field only for a forcing that declares this, so an unforced field, a post-step projection, or a stochastic source carries no rate storage at all. Declaring it is therefore part of implementing set_forcing_rate!, not an optimization: a forcing that fills a rate without declaring one is never given an array to fill, and the ResolvedGenerator constructor rejects it rather than let the forcing go silently unapplied.

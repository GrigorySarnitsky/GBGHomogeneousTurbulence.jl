Propagator

GBGIsotropicTurbulence.Propagator — Module
Propagator

The interchangeable time-marching schemes, concrete AbstractIntegrator subtypes; a run chooses one as the scheme of its Simulation . All are of the integrating-factor family: the stiff diffusive part is advanced exactly and the nonlinear term explicitly by a Runge–Kutta stage combination.

  • AbstractIntegrator — the scheme supertype a run's scheme is chosen from.
  • IFLowStorageRK3, IFRK2 — the schemes (RK3 low-storage; IFRK2/Heun a cheaper two-stage alternative, imaginary-axis unstable).
  • IntegratorBuffers, allocate_buffers — the preallocated per-step scratch.
  • step! — advance the coupled velocity and passive scalar one timestep.
  • deposit! — close the iteration: recover the observables into the cache at the new epoch.
  • recommended_cfl — a scheme's advective-CFL ceiling.

Integrator schemes

The integrating-factor scheme supertype and its concretes — the third-order low-storage RK3, then the cheaper, imaginary-axis-unstable second-order Heun.

GBGIsotropicTurbulence.Propagator.AbstractIntegrator — Type
AbstractIntegrator

Supertype of the time-marching schemes. A scheme implements step!(scheme, state, generator, domain, buffers, cache, dt), advancing the state's velocity $\hat{\boldsymbol{u}}$ and scalar $\hat\varphi$ (both in spectral representation) by one timestep in place, and may specialize recommended_cfl.

source
GBGIsotropicTurbulence.Propagator.IFLowStorageRK3 — Type
IFLowStorageRK3()

Integrating-factor third-order low-storage Runge–Kutta (Williamson 1980, doi:10.1016/0021-9991(80)90033-9; 2N-storage). With the diffusive integrating factor $\mathcal{E}_D(\tau)$ — its parameters supplied by the generator's velocity_integrating_factor / scalar_integrating_factor over a substep interval $\tau$ ($D = \nu$ for the velocity, $\varkappa = \nu/\mathrm{Sc}$ for the scalar) and applied per mode by the backend's fused exponential convolution, never built as a field — and $\widehat{\boldsymbol{N}}$ each field's right-hand side, the step carries a state $\hat q$ and a single accumulator $\boldsymbol{h}$ through three stages $i = 1,2,3$,

\[\begin{aligned} \boldsymbol{h} &\leftarrow A_i \boldsymbol{h} + \Delta t \widehat{\boldsymbol{N}}(\hat q), \\ \hat q &\leftarrow \hat q + B_i \boldsymbol{h}, \\ \hat q &\leftarrow \mathcal{E}_D(d_i\Delta t) \hat q, \\ \boldsymbol{h} &\leftarrow \mathcal{E}_D(d_i\Delta t) \boldsymbol{h}, \end{aligned}\]

(the accumulator's rotation is skipped at the last stage, where nothing reads it again),

with $A = (0, -5/9, -153/128)$, $B = (1/3, 15/16, 8/15)$, and node increments $d = (1/3, 5/12, 1/4)$ (abscissae $c = (0, 1/3, 3/4)$). The velocity and scalar are advanced in lockstep (the same $A,B,d$), each with its own diffusivity, and any post-step forcing is applied after the third stage. Three nonlinear evaluations per step, and — in Williamson's 2N-storage count, whose $N$ counts evolved field registers, not the grid points $N$ of the rest of the documentation — two field registers per field: the state's own array plus one accumulator (stage1; the raw-assembly register nonlinear is the dealiasing seam's addition, not the scheme's). The general-purpose workhorse: third-order and stable on the imaginary axis (limit $\sqrt{3}$), unlike IFRK2.

GBGIsotropicTurbulence.Propagator.IFRK2 — Type
IFRK2()

Integrating-factor second-order Runge–Kutta (Heun). With the velocity and scalar integrating factors $\mathcal{E}_\nu$ and $\mathcal{E}_\varkappa$ (the generator's velocity_integrating_factor / scalar_integrating_factor at $D = \nu$ and $D = \varkappa = \nu/\mathrm{Sc}$ over the step $\Delta t$) and $\widehat{\boldsymbol{N}}$ each field's right-hand side, one step of a field $\hat q$ with integrating factor $\mathcal{E}$ is

\[\begin{aligned} \hat q^{*} &= \mathcal{E} (\hat q_n + \Delta t \widehat{\boldsymbol{N}}_1), \\ \hat q_{n+1} &= \mathcal{E} \hat q_n + \tfrac{\Delta t}{2}(\mathcal{E} \widehat{\boldsymbol{N}}_1 + \widehat{\boldsymbol{N}}_2), \end{aligned}\]

with $\widehat{\boldsymbol{N}}_1$ at $\hat q_n$ and $\widehat{\boldsymbol{N}}_2$ at the predictor $\hat q^{*}$; velocity and scalar use $\mathcal{E}_\nu$ and $\mathcal{E}_\varkappa$ respectively, then the forcings are applied. Two nonlinear evaluations per step.

Note

Every second-order two-stage explicit Runge–Kutta has stability function $R(z) = 1 + z + z^{2}/2$, for which $\lvert R(\mathrm{i}y)\rvert^{2} = 1 + y^{4}/4 > 1$: the scheme is unstable on the imaginary axis, so it is stable only where the viscous damping of the integrating factor dominates. It is adequate for well-resolved, modest-Reynolds-number runs — prefer IFLowStorageRK3 for high Reynolds number or marginal resolution.

Step scratch

The preallocated per-step working set the scheme writes into — built per concrete scheme, sized so a step allocates no field-sized memory.

GBGIsotropicTurbulence.Propagator.IntegratorBuffers — Type
IntegratorBuffers

The preallocated per-step scratch the scheme writes into, sized so a step allocates no field-sized memory. Built per scheme by allocate_buffers(scheme, domain; scalar), which allocates exactly that scheme's working set: an array another scheme would use is left nothing, never allocated.

Each such array is a register: storage a scheme computes one stage into and overwrites at the next, holding nothing a caller should read between steps. The word is used in that sense throughout the package — including for the observables cache's slots, which double as the step's registers mid-iteration.

Fields

  • stage1 — the first Runge–Kutta stage register, allocated by every scheme (the accumulator for IFLowStorageRK3, the first stage for IFRK2).
  • nonlinear — the assembled right-hand side; IFLowStorageRK3 only, else nothing.
  • stage2, velocity_star_spectral — the second stage register and the substage velocity predictor $\hat{\boldsymbol{u}}^{*}$ in spectral representation; IFRK2 only, else nothing.
  • scalar — a ScalarBuffers for the passive scalar $\varphi$ when scalar = true, else nothing; when nothing, the run evolves no scalar and none of its field-sized buffers are allocated. Its fields mirror the per-scheme breakdown above, sized to the scalar: stage1 (every scheme), stage2 and star_spectral (IFRK2's corrector register and predictor state $\hat\varphi^*$), and nonlinear (IFLowStorageRK3 only).

There are deliberately no physical-representation registers here: the substage velocity, vorticity, and scalar recoveries write into the run's ObservablesCache slots, taken as scratch mid-iteration and re-deposited at the iteration's end by deposit! — a slot IS its producer's register. Likewise there is no integrating-factor register: the exact linear subflow is applied by the backend's fused exponential convolution (exponential_convolve!), evaluated per mode from the factor's parameters, so no kernel field is ever built or stored. The right-hand-side assembly scratch (the quadratic products, the phase-shift buffers, the forcing-rate fields) lives with the generator, on the ResolvedGenerator — the buffers here are only the scheme's own spectral stage registers.

GBGIsotropicTurbulence.Propagator.allocate_buffers — Function
allocate_buffers(scheme, domain; scalar = false) -> IntegratorBuffers
allocate_buffers(scheme, tracers) -> ParticleIntegratorBuffers

Allocate the per-step registers a scheme needs, dispatching on the concrete scheme so it allocates exactly its working set — never a register another scheme would use. A scheme with no method here is a hard error; there is no over-allocating fallback. The run layer calls this when assembling a Simulation.

The first form serves the field schemes: it builds the IntegratorBuffers scheme needs, sized to the domain (a FixedDomain, which fixes the grid, precision, and storage backend of every register). IFLowStorageRK3 allocates stage1 and nonlinear; IFRK2 allocates stage1, stage2, and velocity_star_spectral. Passing scalar = true adds the nested ScalarBuffers, likewise sized to the scheme.

The second serves the trajectory schemes: it builds the ParticleIntegratorBuffers the scheme (an AbstractParticleIntegrator) needs, sized to the tracer set tracers. One generic covers both because it is one concept, and because both sides keep the same separation: the evolving state holds no scheme's scratch.

Time stepping

One in-place step of the coupled velocity and passive scalar together through the shared RK stages, and the closing deposit that closes the iteration.

GBGIsotropicTurbulence.Propagator.step! — Function
step!(scheme, state, generator, domain, buffers, cache, dt)

Advance the state (a ResolvedFields holding the velocity $\hat{\boldsymbol{u}}$ and passive scalar $\hat\varphi$ in spectral representation) by one timestep dt in place, using the scheme, the generator (a ResolvedGenerator — the equations of motion, their conditions, and their assembly scratch), the domain (a FixedDomain), the scheme's buffers (an IntegratorBuffers), and the run's observables cache cache (an ObservablesCache ). Dispatches on the concrete scheme type (see IFRK2, IFLowStorageRK3).

A scheme does only stage arithmetic: it opens the step with the generator's prepare! , evaluates the right-hand sides and exact linear factors through the generator protocol at each stage, and closes with the generator's finalize! — it never assembles the physics itself. The first stage reads the deposited velocity, vorticity, and scalar in physical representation from cache — the values of the instant between iterations, where the cache's deposits are current, deposited there by the previous iteration's deposit!; nothing is recomputed on a read — and the later stages compute their recoveries into those same slots, so the step allocates and resides nothing beyond its own spectral stage registers. The cache's fields epoch — the freshness counter every new deposit is recorded at — is advanced when the step completes.

The argument order is shared with deposit!, the call that closes the iteration: the dispatch object leads (the scheme here, the cache there), the common arguments follow in the fixed order state, domain, buffers (with generator after state and cache, dt closing this signature), so the chained pair transposes nothing.

Note

A step! alone leaves the cache mid-iteration (its slots taken as scratch): the caller closes the iteration with deposit!, which re-fills every slot, at the new epoch, from the advanced state — a hand-run loop is step! then deposit!, and the run layer's advance! does both.

Returns state.

GBGIsotropicTurbulence.Propagator.deposit! — Function
deposit!(cache, state, domain, buffers)
deposit!(sim)

Close an iteration: deposit every observable the cache's fixed schedule carries — every slot its configuration holds, the same set every iteration — into cache (an ObservablesCache), from the state (a ResolvedFields ) the step has just produced, and record each slot at the current epoch (the cache's freshness counter). The deposits are the next iteration's first-stage work moved to the iteration's end — the velocity, vorticity, and (when the run carries one) scalar recoveries in physical representation, then the maximum-speed reduction over the just-deposited velocity — so an iteration's transform counts are unchanged by caching, and its pass counts are unchanged but for one: the maximum-speed reduction runs every iteration, including under a hand-fixed $\Delta t$ that never reads it; the recoveries run on the FixedDomain domain's plans, through a spectral stage register of buffers (an IntegratorBuffers) that is dead at the iteration's end.

Every iteration ends with this call: the run layer's advance! performs it after step! , a hand-run loop calls it itself, and the Simulation constructor makes the seeding deposit so the first iteration finds the initial state's observables. The argument order is shared with step! — the mutated dispatch object (here the cache) leads, and state, domain, buffers follow in the same fixed order as there. After mutating the state out of band, announce it with fields_modified! and re-deposit with the second form, which unpacks sim.

Returns cache (or sim).

Timestep ceiling

A scheme's advective-CFL ceiling.

GBGIsotropicTurbulence.Propagator.recommended_cfl — Function
recommended_cfl(scheme, domain)

A conservative advective-CFL (Courant–Friedrichs–Lewy) ceiling $C_{\mathrm{CFL}}$ for the scheme scheme on the FixedDomain domain, for a timestep $\Delta t = C_{\mathrm{CFL}} \Delta x / \max_{\boldsymbol{x}}\lvert\boldsymbol{u}\rvert$, with $\Delta x = L/N$ the grid spacing.

The advective eigenvalues of the dealiased system are imaginary, of magnitude up to $\kappa_{\max}\sup\lvert\boldsymbol{u}\rvert$; stability needs this times $C_{\mathrm{CFL}}$ to stay within the scheme's imaginary-axis stability limit $y_{\mathrm{s}}$. Two loosenesses justify the conservative factor below, and they pull the same way. The speed in the denominator is max_speed, a maximum over grid points, so the continuum $\sup\lvert\boldsymbol{u}\rvert$ between them can be larger; and the eigenvalue bound over-estimates the true spectral radius, since not every mode carries the peak speed. The base ceiling is calibrated for the $2/3$ rule ($\kappa_{\max}\Delta x = 2\pi/3 \approx 2.09$): for IFLowStorageRK3 $y_{\mathrm{s}} = \sqrt{3}$ gives $C_{\mathrm{CFL}} \lesssim 0.83$, taken conservatively as $0.5$; IFRK2 is imaginary-axis unstable ($y_{\mathrm{s}} = 0$, relying on viscous damping), which makes the formula degenerate — its $0.25$ is an empirical margin, not a computed limit, and the damping it leans on weakens as $\nu$ falls.

It scales that base by the domain's dealiasing: a strategy that keeps modes to a higher $\kappa_{\max}$ (e.g. HouLi, out to the Nyquist wavenumber) takes a proportionally smaller step, $C_{\mathrm{CFL}} \propto 1/\kappa_{\max}$. This is the value Simulation uses; override cfl for a specific run.

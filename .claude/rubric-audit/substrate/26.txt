The observables cache of a run — the stamped storage where each iteration deposits, at its end, the
observables its own schedule produces: the velocity ``\\boldsymbol{u}`` and vorticity
``\\boldsymbol{\\omega}`` in physical representation, the scalar ``\\varphi`` in physical
representation when the run carries one, the maximum velocity component (the `max_speed` number
the next timestep choice reads), and — when the run advects tracers — the particle velocities
``\\boldsymbol{u}(t_n, \\boldsymbol{X}(t_n))``. The contents are automatic — derived from the
configuration, never declared: the cache holds exactly what the iteration computes, materializes,
and leaves alive at the iteration's end, and nothing may be added on any cost axis.

Build it on a [`FixedDomain`](@ref) `domain`; pass `scalar = true` when the run evolves a passive
scalar (it adds the scalar's slot), and `particle_velocities` — the tracer set's own point-value
storage — when the run advects tracers (the slot IS that storage, stamped here; the tracers' push
writes it). The `Simulation` front door — the build-everything convenience constructor — builds,
wires, and seeds one for you.

Read through the accessors — [`velocity_physical`](@ref), [`vorticity_physical`](@ref),
[`scalar_physical`](@ref), and `max_speed` — each of which returns the deposited value or throws.
Nothing in the cache is ever recomputed: a read that finds a stale, taken, or never-deposited slot
reports a scheduling error — it throws an `ErrorException` whose message names the slot and which
of the three states it is in — and the only repair is to fix the schedule that failed to deposit.

!!! note
    A slot is also its producer's register: between deposits the step works in the same array, so a
    cached field is only valid between iterations. Treat every returned array as
    read-only — it is the storage the next iteration will work in.

# Fields
- `velocity`, `vorticity` — the cached velocity and vorticity in physical representation (the arrays
  double as the step's stage recovery registers).
- `scalar` — the cached scalar in physical representation, or `nothing` for a scalar-free run.
- `velocity_stamp`, `vorticity_stamp`, `scalar_stamp`, `max_speed_stamp` — each slot's stamp: the
  fields epoch it was deposited at, or a sentinel (never deposited / in use as scratch).
- `max_speed` — the cached maximum velocity component (a host number).
- `particle_velocities` — the particle-velocities slot (the tracer set's own point-value storage,
  whose `(M, 3)` array the accessor extracts with `point_values`), or
  `nothing` for a tracer-free run; `sample_fields_stamp` / `sample_particles_stamp` are its stamps
  against BOTH epochs, since the sample is a function of the state and the positions together.
- `fields_epoch` — the state's epoch: advanced by every completed step and by
  [`resolved_fields_modified!`](@ref); a stamp is current exactly when it equals this.
- `particles_epoch` — the tracer positions' epoch (advanced by the tracer push), the second
  freshness axis of the trajectory-bound slots.
"""
mutable struct ObservablesCache{PV, PS, TS}
  const velocity::PV
  const vorticity::PV
  const scalar::PS
  const particle_velocities::TS
  velocity_stamp::Int
  vorticity_stamp::Int
  scalar_stamp::Int
  max_speed::Float64
  max_speed_stamp::Int
  sample_fields_stamp::Int
  sample_particles_stamp::Int
  fields_epoch::Int
  particles_epoch::Int

A set of Lagrangian tracers, built on `domain`'s backend and element type. The first form seeds `number_of_tracers`
tracers uniformly at random in the periodic box of `domain`; the second wraps a given `(M, 3)` array of
`M` tracer positions (the three columns are the ``x, y, z`` components), converting it to `domain`'s
backend and element type. The `scheme` is the `GBGPeriodicFields` velocity-interpolation scheme used to
evaluate the velocity (and any sampled field) at the tracer positions.
[`CatmullRom`](@extref GBGPeriodicFields GBGPeriodicFields.Interpolation.CatmullRom) is the ``C^1`` choice
(the default `tracer_scheme` of the `Simulation` front door, the build-everything convenience
constructor);
[`LalescuSpline(n, m)`](@extref GBGPeriodicFields GBGPeriodicFields.Interpolation.LalescuSpline) and
[`LagrangeSpline(n)`](@extref GBGPeriodicFields GBGPeriodicFields.Interpolation.LagrangeSpline) offer higher
smoothness or interpolation order — at a wider stencil, useful for derivative-sensitive readouts such as
acceleration statistics — with `n` (and, for `LalescuSpline`, `m`) the stencil and smoothness parameters.
The `rng` (first form only) is the random stream seeding the uniformly-random tracer positions; it
defaults to `Random.default_rng()`.

Read the particle state with [`particle_positions`](@ref) and [`number_of_tracers`](@ref); the
trajectory velocities are read from the run's observables cache (`particle_velocities`), where the
iteration's closing deposit stamps them. The remaining fields are preallocated predictor and
point-value scratch, so the tracer push allocates no per-step memory.

# Fields
- `positions` — the `(M, 3)` tracer positions (read with [`particle_positions`](@ref)).
- `predictor` — `(M, 3)` scratch for the Heun predictor positions.
- `position_points`, `predictor_points` — `PointSet`s wrapping `positions` / `predictor` for interpolation.
- `trajectory_velocity` — the interpolated velocity at the positions the tracers occupy, at the
  instant they occupy them: the genuine Lagrangian sample, and the observables cache's
  particle-velocities slot.
- `predictor_velocity` — the interpolated velocity at the Heun **predictor** positions, which no
  tracer ever occupies: a stage register of the push, never a sample of the flow, and never exposed.
- `scheme` — the velocity-interpolation scheme.
"""
struct Tracers{P, PSX, PSP, VV, S}
  positions::P              # (M, 3)
  predictor::P              # (M, 3) scratch for the Heun predictor
  position_points::PSX      # PointSet wrapping `positions`
  predictor_points::PSP     # PointSet wrapping `predictor`
  trajectory_velocity::VV   # VectorPointValues: u at the occupied positions — the Lagrangian sample
  predictor_velocity::VV    # VectorPointValues: u at the predictor positions — a stage register
  scheme::S
end


function Tracers(domain::FixedDomain, positions::AbstractMatrix; scheme)
  size(positions, 2) == 3 || throw(DimensionMismatch("tracer positions must have shape (M, 3); got $(size(positions))"))
  T = _real_type(domain)
  pos = similar(_reference(domain), T, size(positions))     # the domain's backend + element type
  copyto!(pos, positions)
  predictor = similar(pos)
  return Tracers(pos, predictor,
                 PointSet(pos), PointSet(predictor),
                 VectorPointValues(similar(pos)), VectorPointValues(similar(pos)),
                 scheme)
end

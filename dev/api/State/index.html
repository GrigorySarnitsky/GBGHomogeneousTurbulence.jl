State

GBGIsotropicTurbulence.State — Module
State

The evolving state a run advances, and how it is seeded:

  • ResolvedFields — the evolving velocity and scalar in spectral representation. This is the single source of truth: the physical fields are recovered from it and never held in the state.
  • random_solenoidal_velocity_spectral! and random_scalar_spectral! — the random initial conditions (a divergence-free velocity, a mean-zero scalar) that seed it.

All sized to a FixedDomain.

The recoveries do not disturb the state. An inverse transform consumes the coefficients it runs from, which is a property of the FFT backends rather than a choice, so a naive recovery would destroy the state it read. Recovery therefore goes through the four-argument to_physical!, whose extra argument is a scratch field the transform consumes in the state's place; the vorticity comes from vorticity_physical! instead. The recovered values are deposited into the ObservablesCache.

The state

The evolving fields a run advances, in spectral representation — the single source of truth. The physical representations are recovered from it with the source-preserving four-argument form of to_physical!, and the vorticity with vorticity_physical! — see Observables.

GBGIsotropicTurbulence.State.ResolvedFields — Type
ResolvedFields(domain; scalar = false)

The record of the evolving fields a run advances, in spectral representation — the single source of truth. The velocity, vorticity, and scalar in physical representation are recoveries of it, not part of it: each iteration — one advance of the run, a step plus the deposit that closes it — recovers them at its end into the ObservablesCache, so the state itself cannot go stale.

Build it on a FixedDomain; pass scalar = true to carry a passive scalar.

Fields

  • velocity_spectral — the velocity in spectral representation, $\hat{\boldsymbol{u}}$.
  • scalar_spectral — the scalar in spectral representation, $\hat\varphi$, or nothing when the run carries no passive scalar.

Random initial conditions

Seed a large-scale-peaked, dealiased, rescaled random solenoidal velocity, or a mean-zero scalar.

GBGIsotropicTurbulence.State.random_solenoidal_velocity_spectral! — Function
random_solenoidal_velocity_spectral!(û, domain; kinetic_energy, envelope_wavenumber,
                            spectrum = nothing, rng = default_rng())

Fill û (a velocity field in spectral representation) with a random, divergence-free velocity $\boldsymbol{u}$ of a chosen energy spectrum, dealiased and rescaled so the kinetic energy $\tfrac{1}{2}\langle\lvert\boldsymbol{u}\rvert^{2}\rangle$ equals the requested kinetic_energy. The Leray–Helmholtz projection $\mathbb{P}$ enforces $\nabla\cdot\boldsymbol{u} = 0$.

By default (spectrum = nothing) the velocity is concentrated at large scales by a Gaussian envelope $\exp\!\bigl(-\lvert\boldsymbol{\kappa}\rvert^{2}/\kappa_p^{2}\bigr)$ on the mode amplitudes (zeroed at $\boldsymbol{\kappa} = \boldsymbol{0}$, so the mean mode stays empty), whose characteristic wavenumber is $\kappa_p$ (envelope_wavenumber). Because the envelope multiplies the amplitudes, the shell-summed energy spectrum $\propto \kappa^{2}\exp\!\bigl(-2\kappa^{2}/\kappa_p^{2}\bigr)$ peaks at $\kappa_p/\sqrt{2}$, not at $\kappa_p$ itself (the $\kappa^{2}$ is the shell's mode count). Pass spectrum, a function $\kappa \mapsto E(\kappa)$ giving a target radial energy spectrum, to seed that shape instead: each mode is scaled by $\sqrt{E(\kappa)}/\kappa$, so the shell-summed spectrum is $\propto \kappa^{2}(\sqrt{E}/\kappa)^{2} = E(\kappa)$ (the $\kappa^{2}$ is the shell's mode count) and the overall amplitude is fixed by the kinetic_energy rescaling — e.g. a von Kármán or Pope form from the Phenomenology submodule's model spectra, which the run layer can wire in for you.

The domain (a FixedDomain) is what the field is generated on; the rng is the random stream (defaults to Random.default_rng()).

Seeding a running case invalidates the observables cache

The cache holds what the last deposit left, so a seed written into a live run makes every cached observable wrong. Announce the change with fields_modified!, which advances the fields epoch — the cache's freshness counter — so cached reads throw rather than serve stale values, then restore the cache with deposit! before advancing again. The interval between the two calls is yours to close.

GBGIsotropicTurbulence.State.random_scalar_spectral! — Function
random_scalar_spectral!(φ̂, domain; scalar_variance, envelope_wavenumber,
               spectrum = nothing, rng = default_rng())

Fill φ̂ (the scalar $\varphi$ in spectral representation) with a random, mean-zero scalar of a chosen spectrum, dealiased and rescaled so the variance $\langle\varphi^{2}\rangle$ equals the requested scalar_variance. The mean vanishes by construction: the envelope is zeroed at $\boldsymbol{\kappa}=\boldsymbol{0}$, and that mode's coefficient is the spatial mean $\langle\varphi\rangle$.

By default (spectrum = nothing) the scalar is concentrated at large scales by a Gaussian envelope $\exp\!\bigl(-\lvert\boldsymbol{\kappa}\rvert^{2}/\kappa_p^{2}\bigr)$ on the mode amplitudes — zeroed, as above, at the origin — whose characteristic wavenumber is $\kappa_p$ (envelope_wavenumber). Because the envelope multiplies the amplitudes, the shell-summed scalar-variance spectrum $\propto \kappa^{2}\exp\!\bigl(-2\kappa^{2}/\kappa_p^{2}\bigr)$ peaks at $\kappa_p/\sqrt{2}$, not at $\kappa_p$ itself (the $\kappa^{2}$ is the shell's mode count). Pass spectrum, a function $\kappa \mapsto E_\varphi(\kappa)$ giving a target radial scalar-variance spectrum, to seed that shape instead: each mode is scaled by $\sqrt{E_\varphi(\kappa)}/\kappa$ (the same construction the velocity uses), so the shell-summed spectrum is $\propto E_\varphi(\kappa)$ and the amplitude is fixed by the scalar_variance rescaling — e.g. an Obukhov–Corrsin form from Phenomenology.

The domain (a FixedDomain) is what the field is generated on; the rng is the random stream (defaults to Random.default_rng()).

Seeding a running case invalidates the observables cache

The cache holds what the last deposit left, so a seed written into a live run makes every cached observable wrong. Announce the change with fields_modified!, which advances the fields epoch — the cache's freshness counter — so cached reads throw rather than serve stale values, then restore the cache with deposit! before advancing again. The interval between the two calls is yours to close.

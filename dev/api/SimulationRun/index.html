SimulationRun

GBGIsotropicTurbulence.SimulationRun — Module
SimulationRun

The run layer:

  • Simulation — everything the next iteration needs, in one value: the domain, the fields at the current instant, the observables cache, the equations of motion with their forcing, the integration schemes with their scratch, any tracers, and the clock — built with defaults from a few numbers. It holds the present instant — plus the one bounded look-back a multistep particle scheme needs, the cache's Lagrangian sample history — and past instants otherwise exist only in what an observation recorded as the run advanced.
  • advance!, run! — advance one iteration; observe and advance until the callback stops the run (the callback is the observation — the function the loop calls to read the run each iteration — and its return decides continuation).
  • StationarityCriterion, warmup! — the packaged spin-up-to-stationarity observation, and warmup!, the one-line shorthand that runs it.
  • current_time, current_step — the elapsed time and step count.
  • flow_parameters — the run's measured flow state as a Phenomenology FlowParameters.
  • write_simulation / read_simulation — checkpoint and restore: the restartable run as one self-describing HDF5 group (available once HDF5 is loaded).

Read a run's state through sim.state and its deposited observables through sim.cache, with the observables and cache accessors that own them; the run layer adds no forwarding methods of its own.

The simulation

The assembled, ready-to-run simulation — the domain-building Simulation(; grid_points_per_axis, viscosity, …) and the domain-taking Simulation(domain; …) constructors. Read its measured state by applying the Observables to sim.state — for example kinetic_energy(sim.state.velocity_spectral) in a run! callback.

GBGIsotropicTurbulence.SimulationRun.Simulation — Type
Simulation(; grid_points_per_axis, κ_max_η = nothing, kinetic_energy = 1.5,
             side_length = 2π, element_type = Float64, array_type = Array,
             dealiasing = TwoThirds(), kwargs...)
Simulation(domain; κ_max_η = nothing, kinetic_energy = 1.5, kwargs...)

Everything the next iteration needs, bundled: the FixedDomain, the IntegratorBuffers, the ResolvedGenerator (the equations of motion, carrying the FlowConditions and the assembly scratch), the chosen field integration scheme, the ResolvedFields state (the velocity $\hat{\boldsymbol{u}}$ and passive scalar $\hat\varphi$ in spectral representation), the ObservablesCache holding what the last iteration deposited, any Tracers, and a clock.

The two forms differ only in where the FixedDomain comes from. The first is domain-building: from grid_points_per_axis and side_length it builds the domain and every piece above it with sensible defaults, seeds a divergence-free velocity (and, with scalar = true, a mean-zero scalar $\varphi$), and returns a Simulation at $t = 0$. The second is domain-taking: the same assembly on a FixedDomain you built yourself.

Advance it with advance! / run! / warmup!. Read its measured state by applying the observables to sim.state (e.g. kinetic_energy(sim.state.velocity_spectral)) or through the cache's deposited observables (velocity_physical(sim.cache)); summarize it with flow_parameters, and track its progress with current_time / current_step.

Setting the Reynolds number

By default the run is forced and stationary — a VarianceController drives the whole-field kinetic energy to the value given by the kinetic_energy keyword and holds it there — and the viscosity is chosen from the grid rather than supplied:

  • Derived viscosity (no viscosity passed explicitly): the constructor picks the highest Reynolds number consistent with the resolution criterion κ_max_η, in two steps.

    First it estimates the dissipation the box sustains, from the box-normalized law Li2008 (in Phenomenology.Scalings): $\varepsilon = (k/G)^{3/2}/L$, with kinetic_energy the energy $k$, side_length the side $L$, and $G \approx 0.9$ a dimensionless constant. $G$ carries $C_\varepsilon^{-2/3}$ and the ratio $L_{11}/L$, and that ratio is set by where a run is forced — so the estimate assumes forcing in the same low shells as the runs it was calibrated on, and a forcing moved higher invalidates it.

    Then it sets $\nu$ so that $\kappa_{\max}\eta$ equals κ_max_η, with $\kappa_{\max}$ the max_resolved_wavenumber and $\eta$ the Kolmogorov microscale. Since $\kappa_{\max}\eta = f\pi\eta/\Delta x$ with $f$ the resolved-Nyquist fraction, κ_max_η = 2 gives $\Delta x \approx \eta$ under the default $2/3$ rule.

    The criterion measures the resolved band, strategy by strategy

    $\kappa_{\max}$ here is each strategy's resolved cutoff — for HouLi that is $\tfrac{4}{5}\kappa_{\mathrm{Ny}}$, where its per-step damping overtakes viscosity, not the Nyquist its energetic band reaches — so equal κ_max_η means equally trusted dynamics across strategies. Strategies still reach different Reynolds numbers on the same grid, but for the honest reason that their resolved bands differ: with $\nu \propto f^{-4/3}$, HouLi gives $\mathrm{Re}_\lambda$ about 13% and PhaseShift about 26% above the $2/3$ rule.

    The grid and κ_max_η together fix $\mathrm{Re}_\lambda \sim N^{2/3}$; kinetic_energy and side_length fix the units. The chosen $\nu$, $\varepsilon$ and $\mathrm{Re}_\lambda$ are logged.

    One precondition: the choice is self-consistent only if the run holds $k$ near kinetic_energy. The default VarianceController does, to the tolerance its gain sets — its restoring term measures the whole-field $k$, which is the quantity assumed here. Give the velocity a forcing that lets $k$ float, or one holding some other quantity (a VarianceRescaling(over = :band) holds the band instead), and the $\nu$ chosen here no longer matches the run.

  • Supplied viscosity: pass viscosity and it is used directly; the two are alternatives, and passing both raises an ArgumentError rather than dropping one — for a decaying run (velocity_forcing = NoForcing()) or manual control. The derived viscosity is calibrated on a stationary forced balance (Li2008's $G$ is fitted to forced-isotropic DNS), so a decaying run should set $\nu$ explicitly: the resolution it buys is only meaningful while the box sustains the energy the law assumes.

Arguments

All keyword except domain. The keywords split as the two forms do: the domain group is consumed by the domain-building form, and the domain-taking form replaces the whole group with its one positional argument; the run group is accepted by both.

The domain group:

  • domain — a pre-built FixedDomain: the positional argument of the domain-taking form, standing in for every other keyword of this group.
  • grid_points_per_axis — the number of grid points $N$ along each side; required.
  • side_length = 2π — the box side $L$.
  • element_type = Float64, array_type = Array — the real element type and storage backend.
  • dealiasing = TwoThirds() — the DealiasingStrategy ($2/3$ sharp, HouLi smooth, or PhaseShift); it sets the retained band (hence the CFL step) and the resolved band (hence the $\kappa_{\max}$ of κ_max_η).

The run group:

  • κ_max_η — the resolution criterion $\kappa_{\max}\eta$ a derived $\nu$ is set from; $\ge 1.5$ is well-resolved, higher trades Reynolds number for margin. It defaults to nothing and the derivation then uses 2; the sentinel is what lets the constructor tell an omitted keyword from an explicit one, so that giving both it and viscosity is an error rather than a silent drop.
  • viscosity — the kinematic viscosity $\nu$, which is how the Reynolds number is set (it is $1/\nu$ only in units where $u' = L = 1$; measure $\mathrm{Re}_\lambda$ for the run's actual value); omit to derive $\nu$ from the grid.
  • kinetic_energy = 1.5 — the initial, and when forced the held, kinetic energy $k$; 1.5 gives an r.m.s. velocity $u' = \sqrt{2k/3} = 1$.
  • schmidt = 1.0 — the Schmidt number $\mathrm{Sc}$ (scalar diffusivity $\varkappa = \nu/\mathrm{Sc}$). The resolution criterion covers the velocity, not the scalar, whose cutoff at $\mathrm{Sc} > 1$ is the finer Batchelor scale $\eta_B = \eta/\sqrt{\mathrm{Sc}}$ — under-resolved by $\sqrt{\mathrm{Sc}}$ on the same grid, with scalar_dissipation then measuring a truncated field. The package targets $\mathrm{Sc} = O(1)$, with no Batchelor-range machinery. The constructor warns when the run's $\kappa_{\max}\eta_B$ falls below the $1.5$ well-resolved floor — in either viscosity mode, since the check reads the resolved $\nu$ however it was obtained — a warning, not an error, so a deliberately under-resolved scalar stays reachable but not silent; the remedy is κ_max_η raised by $\sqrt{\mathrm{Sc}}$, or viscosity set by hand.
  • scalar = false, scalar_variance = 1.0 — whether to evolve a passive scalar (a mean-zero $\varphi$), and its initial variance.
  • velocity_forcing, scalar_forcing — an AbstractForcing (or a DeferredForcing from an operator-free constructor); velocity_forcing left at nothing means the default — a VarianceController driving the whole-field kinetic energy to the kinetic_energy value — and scalar_forcing defaults to NoForcing(). The velocity and scalar are forced independently. A VarianceController with a defaulted turnover_time is refused as scalar_forcing (its derived settling time reads the target as a kinetic energy) — pass the flow's turnover time explicitly there. Under a derived ν a hand-built velocity forcing is checked against the ν calibration: one that holds a different target, a band instead of the whole field, or nothing at all draws a warning, since the chosen ν then describes a state the run never reaches.
  • envelope_wavenumber = 2.0 — the large-scale envelope wavenumber $\kappa_p$ of the initial condition, for the velocity and the scalar alike (each shell-summed spectrum peaks at $\kappa_p/\sqrt{2}$); it does not shape the profile when initial_spectrum is given (the model does), but it still sets the integral scale of the assumed state that model is evaluated at. Keep $\kappa_p$ well below the dealias cutoff: a value near or above it concentrates the pre-rescale seed in shells the mask holds empty; the seeders warn when the envelope's peak reaches the cutoff (a model-spectrum seed is shaped by its model instead and is not guarded).
  • initial_spectrum = nothing — draw the initial velocity from a Phenomenology EnergySpectrum (say VonKarman1948()) instead of the default large-scale Gaussian. A model spectrum needs a flow state, and at $t = 0$ there is nothing measured yet, so one is assumed — a stand-in, not a measurement of the field about to be seeded. The assumed state reads: $\varepsilon$ from the Li2008 stationary-dissipation law at the requested kinetic_energy and box side, $u'$ from that same energy, $\nu$ as resolved above, and 1/envelope_wavenumber for the integral scale (rather than the $L_{11}$ the seeded field will actually have). Note the $\varepsilon$ half: it is the stationary forced estimate, so on a decaying run the model's dissipation-range placement is misplaced from the start. That failed balance is the same reason the explicit-$\nu$ advice above exists. The seeded field is then normalized to kinetic_energy, so the model fixes the shape and the assumed state only positions it. This shapes the velocity only; a scalar is always seeded from the default Gaussian envelope, and a scalar-spectrum initial condition is reached by calling random_scalar_spectral! on the built run and announcing the change with fields_modified!.
  • field_integration_scheme = IFLowStorageRK3(), cfl = recommended_cfl(field_integration_scheme, domain) — the AbstractIntegrator scheme (IFSSPRK3 and IFHeun are the alternatives) and its advective-CFL ceiling (adapts to dealiasing).
  • max_dt = Inf — a further ceiling on the adaptive timestep, stated in the run's own time units, and off unless set. The adaptive step is the smallest of three bounds: the advective rule $\Delta t = C\Delta x / u_{\max}$, the longest mode's diffusive-decay time $1/(D\kappa_{\min}^{2})$ — with $\kappa_{\min} = 2\pi/L$ the box's fundamental wavenumber and $D$ the larger of the run's diffusivities ($\nu$, and $\varkappa = \nu/\mathrm{Sc}$ when a scalar rides), since the faster-diffusing field decays first — and this. The advective rule alone diverges as a decaying flow approaches rest — past some step the integrating factor annihilates every mode and the clock advances by a number that means nothing — and it is the diffusive-decay bound that stops that, needing no constant from the caller. max_dt is for a ceiling only the caller knows, since any default constant would be a claim about the velocity scale they happened to choose.
  • number_of_particles = 0, interpolation_scheme = nothing, unwrapped = false — the number of Lagrangian Tracers, the spatial scheme that evaluates a field at their positions (nothing means the default CatmullRom), and whether to also track the winding-preserving unwrapped positions (read with unwrapped_positions — what a mean-square-displacement diagnostic needs); all three forwarded to the Tracers constructor. A particle-only setting given on a particle-free run is refused rather than silently discarded.
  • particle_integration_scheme = nothing — the scheme that advances the trajectories in time, an AbstractParticleIntegrator (nothing means the default Heun); its registers — the per-step scratch that scheme needs, meaningless to read between calls — are allocated for you. Pass AdamsBashforth() when trajectory accuracy in time limits a measurement: it costs one stored array per extra order and saves an interpolation per step.
  • rng — the random stream for the initial condition and the tracer seeding (defaults to Random.default_rng()).

Examples

The two ways in, and the two ways to set the Reynolds number:

# Derived viscosity — a 128³ forced-stationary run, ν set from the resolution criterion:
sim = Simulation(grid_points_per_axis = 128)

# Supplied viscosity — set ν directly, carry a passive scalar, force at constant power:
sim = Simulation(grid_points_per_axis = 128, viscosity = 1e-2;
                 scalar = true, velocity_forcing = ConstantPower(injection_rate = 0.1))

# Domain-taking — build the frame yourself, then hand it over:
domain = FixedDomain(; grid_points_per_axis = 128, side_length = 2π, dealiasing = HouLi(),
                     element_type = Float64, array_type = Array)
sim = Simulation(domain; viscosity = 1e-2)
The default drives the kinetic energy to a set value, so read it as a control target

VarianceController restores $k$ exponentially to kinetic_energy, pinning $u'$ and the scale of $\mathrm{Re}_\lambda$. It does not impose the value step by step as a rescale does, so the fluctuation it leaves is genuine — but it is a controlled variable's fluctuation, with the gain setting its amplitude. For the free fluctuation of $k$, force with fixed injection (ConstantPower) instead.

Fields

Three of these are what a user reads — state, cache, and tracers. The rest are the machinery the step runs on: they hold partial values while a step is in flight, so read them only between steps, and treat their contents as the scheme's business rather than the run's state.

  • state — the ResolvedFields (the evolving û, φ̂).
  • cache — the ObservablesCache: the observables the iteration deposits at its end.
  • domain, buffers, generator, field_integration_scheme — the FixedDomain, IntegratorBuffers, the ResolvedGenerator (whose conditions field is the run's FlowConditions), and the chosen scheme.
  • tracers, particle_integration_scheme, particle_buffers — the Tracers being advected along with the fields, the scheme advancing them along their trajectories, and that scheme's registers. All nothing when the run carries no tracers.
  • cfl, clock — the advective-CFL coefficient, and the time/step counter.

Advancing the run

Advance one iteration, or observe-and-advance until the callback stops the run; the packaged stationarity observation and its one-line shorthand spin a fresh run up to measurement readiness.

GBGIsotropicTurbulence.SimulationRun.StationarityCriterion — Type
StationarityCriterion(; gate_scalar = true, gate_skewness = false, min_turnovers = 5,
                        window_turnovers = 4, tol = 0.05, skew_floor = 0.1,
                        max_turnovers = 60)

The packaged spin-up observation for run!: a callback that watches the run settle into statistical stationarity and stops it there — run!(StationarityCriterion(), sim) is the detecting spin-up, and warmup! is the one-line shorthand for exactly that call. Use it before measurement on any freshly seeded forced run. A freely decaying run (NoForcing()) has no stationary state to detect — its $\varepsilon$ never plateaus — so the criterion can only run to max_turnovers and warn; give a decaying run a fixed-length loop instead, which is a three-line callback (see run!).

At each iteration it measures the dissipation $\varepsilon$ and the kinetic energy $k$, accumulates the eddy-turnover clock $\Delta t \varepsilon/k$, and tests $\varepsilon$ for flatness over a trailing window; it stops the run when every gate holds, or gives up with a warning at max_turnovers. The gate reads $\varepsilon$ alone: the small scales settle last, so a flat $\varepsilon$ is the strict indicator — where $k$ is whatever the forcing shapes: clamped by a rescale, driven toward its target by the default controller, ringing under fixed injection — so its flatness would certify the forcing, not the flow.

Arguments

  • gate_scalar — when the run's scalar is forced, also require the scalar variance $\langle\varphi^2\rangle$ to be flat (the scalar settles after the velocity; an unforced scalar has no stationary state and is never gated).
  • gate_skewness — also require the velocity-derivative skewness to have plateaued and reached $\lvert S\rvert \ge \texttt{skew\_floor}$ — the "real turbulence yet" signal, exactly as strict as its floor (see skew_floor below): a random-phase field starts at $S \approx 0$ and only a developed cascade reaches $S \approx -0.5$. It is off by default, and turning it on is the stricter spin-up: the $\varepsilon$ gate alone can be satisfied by a field whose cascade is not yet developed, so a run whose measurement depends on the small scales should set it. The cost is why it is not the default — the skewness is the only observation here that transforms a rank-2 field, so it alone builds the domain's rank-2 plans, and on a GPU backend those are the larger part of a run's plan residency. When it is on, the skewness is measured on the criterion's own sampling interval — one sample per window_turnovers / 40 of turnover time, giving about forty samples across the trailing window — rather than every iteration.
  • min_turnovers, window_turnovers, tol — do not test before min_turnovers eddy-turnover times (past the start-up overshoot); flatness is a two-half-window mean comparison over the trailing window_turnovers, relative drift below tol.
  • skew_floor — the minimum $\lvert S\rvert$ for a plateau to count as developed turbulence. The default 0.1 is a floor against a random-phase field, which starts at $S \approx 0$; it is a fifth of the $\lvert S\rvert \approx 0.5$ of a developed cascade, so clearing it means "no longer Gaussian", not "fully developed". Raise it toward 0.4 when the run's statistics depend on the cascade being mature.
  • max_turnovers — the give-up cap: reaching it stops the run with a warning rather than spinning forever.

The criterion carries its own observation state (the sampled signals and the turnover clock), so build a fresh one per run.

Fields

The fields are not the keywords: gate_skewness, min_turnovers, window_turnovers, tol and skew_floor all live inside monitor, which holds the sampled series together with the thresholds that judge them. Build one through the keyword constructor above.

  • monitor — the sampled signal series ($\varepsilon$, the scalar variance, the skewness — not $k$, which this criterion deliberately never gates on), each recorded against the turnover clock's readings, and the gate settings and tolerances that test them.
  • max_turnovers — the give-up cap.
  • gate_scalar — the requested scalar gate (applied only when the run's scalar is forced).
  • elapsed_turn, last_time, started — the turnover clock itself: the accumulated turnovers, the instant last read, and whether the clock has started.

GBGIsotropicTurbulence.SimulationRun.advance! — Function
advance!(sim; dt = nothing)

Advance sim by one timestep in place and return it.

The arguments are:

  • sim — the Simulation to advance.
  • dt = nothing — pass a value to force a fixed step; nothing picks the adaptive step, the smallest of the advective-CFL value for the current velocity, the longest mode's diffusive-decay time (the same diffusive-decay bound the Simulation docstring states), and max_dt.

Closes the iteration with deposit!, so the cache is readable when it returns. Advects the tracers, if any, under the run's chosen particle integration scheme, and updates the clock.

Returns sim.

GBGIsotropicTurbulence.SimulationRun.run! — Function
run!(callback, sim)
run!(sim) do sim … end

Observe and advance sim until the observation stops it.

After every iteration — and once at the seeded initial state, before any advance — the callback observes the run as callback(sim): it reads the state and the cached observables, records what it wants, and returns true to continue or false to stop. Any other return throws an ArgumentError.

Only then does the next iteration run: the timestep from the cached maximum speed, the step, the tracer advance, and the closing deposits. A run of $n$ iterations therefore observes $n + 1$ instants — the first before any step, the last after the final one, with statistics recorded before the stop.

Stopping is the observation's decision on observables, never a run option. A span of simulation time compares current_time against a target; a step budget compares current_step; an eddy-turnover budget accumulates $\Delta t \varepsilon/k$ from the observables it computes; spin-up to stationarity is the packaged StationarityCriterion. Whatever the callback needs beyond the cached observables it computes itself, at its own cadence, with the exported reductions and recoveries.

Examples

run!(sim) do s
    current_time(s) < 5.0                        # a span of simulation time
end

history = Float64[]                              # record k every iteration; stop at 200 steps
run!(sim) do s
    push!(history, kinetic_energy(s.state.velocity_spectral))
    current_step(s) < 200
end

run!(StationarityCriterion(), sim)               # spin up to statistical stationarity

Returns sim.

GBGIsotropicTurbulence.SimulationRun.warmup! — Function
warmup!(sim; kwargs...)

A one-line shorthand, and nothing more: warmup!(sim; kwargs...) is exactly

run!(StationarityCriterion(; kwargs...), sim)

— it spins sim up to a statistically stationary state before measurement and returns it, by running the observation-first loop with the packaged stationarity observation. Every keyword is passed through to StationarityCriterion untouched; its docstring is the home for what is detected (the flat dissipation, the scalar-variance and derivative-skewness gates, the give-up cap) and for every option. For a fixed spin-up budget, write the three-line budget callback instead (see run!).

Examples

warmup!(sim)                         # detect stationarity on the ε-plateau gate
warmup!(sim; gate_skewness = true)   # also require a developed cascade (stricter, and costlier)

Returns sim.

GBGIsotropicTurbulence.SimulationRun.current_step — Function
current_step(sim)

The number of steps sim has taken — how far the run has gone.

Distinct from the observables cache's epoch, which counts changes to the state rather than advances of the run: a completed step advances the epoch, but so does any announced out-of-band mutation. The constructor's seeding deposit already leaves the fields epoch at 1, so after two steps and one announced mutation the clock reads step 2 and the fields epoch reads 4. Use this to ask how far the run has gone, and the epoch to ask whether a cached value is still the right one.

Flow parameters

Bridge the run's measured state to a Phenomenology FlowParameters, so any reference law can be evaluated at the run's measured state.

GBGIsotropicTurbulence.SimulationRun.flow_parameters — Function
flow_parameters(sim)

The measured flow state of sim as a FlowParameters — the bridge that lets any Phenomenology reference law be evaluated at the run's measured state. The viscosity $\nu$ and the Schmidt number are read from the generator's conditions; the dissipation $\varepsilon$, the r.m.s. velocity $u' = \sqrt{2k/3}$ (from the kinetic energy $k$), the longitudinal integral scale $L_{11}$, and — when the run carries a scalar — the scalar dissipation $\varepsilon_\varphi$ are measured from the current state (the scalar dissipation is left NaN only for a scalar-free run, where the scalar reference laws do not apply).

Persistence

Checkpoint and restore — the restartable run as one self-describing group, available once HDF5 is loaded.

GBGIsotropicTurbulence.SimulationRun.write_simulation — Function
write_simulation(parent::HDF5.H5DataStore, name::AbstractString, sim::Simulation)

Checkpoint the run: write everything needed to restore sim (a Simulation) as one self-describing HDF5 group — the domain's parameters, the state in spectral representation, the tracer set, both forcing strategies, the Lagrangian sample history a multistep particle integration scheme integrates over, the scheme and timestep settings, and the clock. Nothing derivable is stored: the physical-representation observables, the current velocity sample, and every register and plan are recomputed on read. A stochastic forcing — none currently ships; the one implementation is archived — has its evolving state deliberately not stored (its parameters are), so continuation is exact for deterministic forcings.

Available once the HDF5 package is loaded; opening and closing the file is the caller's job, and parent[name] = sim is equivalent sugar.

The arguments are:

  • parent — the open HDF5 file or group to write under.
  • name — the created group's name.
  • sim — the run to checkpoint.

Returns the created group. Restore with read_simulation.

GBGIsotropicTurbulence.SimulationRun.read_simulation — Function
read_simulation(parent::HDF5.H5DataStore, name::AbstractString;
                array_type = Array) -> Simulation

Restore a run from the group write_simulation wrote: rebuild the Simulation through its own constructor from the recorded parameters, overwrite the freshly seeded state and positions with the stored ones, re-deposit every observable the schedule carries, restore the Lagrangian sample history fill-aware (a scheme of a different order keeps what fits and bootstraps the rest), and set the clock — the next advance! continues the checkpointed run. The one deliberate divergence is a stochastic forcing (none currently ships — the one implementation is archived), which resumes on a fresh stream. A group not written by write_simulation, or written by a newer schema version, is refused with an ArgumentError. Available once the HDF5 package is loaded.

The arguments are:

  • parent — the open HDF5 file or group holding the checkpoint group.
  • name — the group's name.
  • array_type = Array — the storage backend the restored run lives on; the reader names it, so a checkpoint written on one backend loads on any other.

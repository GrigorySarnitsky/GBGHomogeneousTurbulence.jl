Cache

GBGIsotropicTurbulence.Cache — Module
Cache

The observables cache — the stamped storage where the iteration leaves the observables it produces, for the run's own components and any observation to read:

  • ObservablesCache — the cache itself: the slots, their stamps, and the epoch counters.
  • velocity_physical, vorticity_physical, scalar_physical — the checked reads of the cached fields (the velocity, vorticity, and scalar in physical representation).
  • max_speed — the cached maximum speed, the number the timestep choice reads (one generic with the field reduction in Observables, whose docstring is the home).
  • resolved_fields_modified! — announce a state mutation made outside the iteration, so every stamp is cleared and reads throw until the next deposit.

The deposit and take verbs (deposit_velocity!, take_velocity!, …) are the solver components' side of the contract; a caller reads through the accessors and never deposits.

The observables cache

The stamped boundary storage the iteration deposits its observables into — every read serves the deposited value or throws, and nothing is ever recomputed on a read.

GBGIsotropicTurbulence.Cache.ObservablesCache — Type
ObservablesCache(domain; scalar = false)

The observables cache of a run — the stamped storage where each iteration deposits, at its tail, the observables its own schedule produces: the velocity $\boldsymbol{u}$ and vorticity $\boldsymbol{\omega}$ in physical representation, the scalar $\varphi$ in physical representation when the run carries one, and the maximum speed $\max_i\lvert u_i\rvert$ (the number the next timestep choice reads). The contents are automatic — derived from the configuration, never declared: the cache holds exactly what the iteration computes, materializes, and leaves alive at the boundary, and nothing may be added on any cost axis.

Build it on a FixedDomain domain; pass scalar = true when the run evolves a passive scalar (it adds the scalar's slot). The Simulation front door builds and seeds one for you.

Read through the accessors — velocity_physical, vorticity_physical, scalar_physical, and max_speed — each of which returns the deposited value or throws. Nothing in the cache is ever recomputed: a read that finds a stale, taken, or never-deposited slot reports a scheduling error, and the only repair is to fix the schedule that failed to deposit.

Note

A slot is also its producer's register: between deposits the step works in the same array, so a cached field is only valid at the boundaries between iterations. Treat every returned array as read-only — it is the storage the next iteration will work in.

Fields

  • velocity, vorticity — the cached velocity and vorticity in physical representation (the arrays double as the step's stage recovery registers).
  • scalar — the cached scalar in physical representation, or nothing for a scalar-free run.
  • velocity_stamp, vorticity_stamp, scalar_stamp, max_speed_stamp — each slot's stamp: the fields epoch it was deposited at, or a sentinel (never deposited / in use as scratch).
  • max_speed — the cached maximum speed (a host number).
  • fields_epoch — the state's epoch: advanced by every completed step and by resolved_fields_modified!; a stamp is current exactly when it equals this.
  • particles_epoch — the tracer positions' epoch (advanced by the tracer push), for the trajectory-bound observables.

GBGIsotropicTurbulence.Cache.resolved_fields_modified! — Function
resolved_fields_modified!(cache)
resolved_fields_modified!(sim)

Announce that the resolved fields — the spectral $\hat{\boldsymbol{u}}$, $\hat\varphi$ — were changed outside the iteration (a re-seeded velocity, any direct write to the state's storage). Advances the fields epoch, so every cached observable is stale and reads throw until the next deposit; that interval belongs to whoever made the change. Returns the cache (or sim).

The sanctioned mutators call this for you: step! advances the epoch itself when it completes, and the iteration's tail deposit then restores the cache. After a hand-made mutation, re-deposit with the run layer's deposit! before advancing again — the timestep choice reads the cached maximum speed.

source

The checked reads

Each accessor returns the observable deposited at the current boundary, or throws; the cached maximum speed is read through max_speed, documented with the reduction it stores.

GBGIsotropicTurbulence.Cache.velocity_physical — Function
velocity_physical(cache)

The velocity $\boldsymbol{u}$ in physical representation at the current boundary — the checked read of the ObservablesCache cache's velocity slot. Returns the deposited field when its stamp is current, and throws otherwise (the slot is mid-iteration scratch, stale, or was never deposited); nothing is ever recomputed on a read. Treat the returned field as read-only — it is the storage the next iteration works in.

source
GBGIsotropicTurbulence.Cache.vorticity_physical — Function
vorticity_physical(cache)

The vorticity $\boldsymbol{\omega} = \nabla\times\boldsymbol{u}$ in physical representation at the current boundary — the checked read of the ObservablesCache cache's vorticity slot, with exactly velocity_physical's contract (the deposited field or a throw; never a recomputation; read-only).

source
GBGIsotropicTurbulence.Cache.scalar_physical — Function
scalar_physical(cache)

The scalar $\varphi$ in physical representation at the current boundary — the checked read of the ObservablesCache cache's scalar slot, with exactly velocity_physical's contract (the deposited field or a throw; never a recomputation; read-only). Throws an ArgumentError when the run carries no scalar.

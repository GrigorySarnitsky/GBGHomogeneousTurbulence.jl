Cache

GBGHomogeneousTurbulence.Cache — Module
Cache

The observables cache — where the iteration leaves the observables it produces, so that the run's own components, and the caller between iterations, read them instead of computing them again. Each value is deposited, written together with its epoch: the version of the state it was computed from, a number raised by one with each step and each tracer push.

The cache's operations:

  • ObservablesCache — the cache itself: the slots, their epochs, and the two counters.
  • velocity_physical, vorticity_physical, scalar_physical — the checked reads of the cached fields (the velocity, vorticity, and scalar in physical representation).
  • max_speed — the cached largest flow speed, the number the timestep choice reads (one generic with the field reduction in Observables, whose docstring is the home).
  • velocity_at_particles_trail — the checked read of the velocity sampled along each trajectory: its last few samples, the newest first.

The field slots are filled by deposit!, which Propagator owns rather than this module because it needs the scheme's scratch to recover the fields. Each slot carries both the value and the epoch that value belongs to, so a read can be refused rather than served stale.

The solver's side of the contract is that deposit! fills every field-derived slot at the iteration's end (the trail of the velocity at the particles receives its new sample from the same generic's particle form, after the tracers advance) and sets its epoch. A caller reads through the accessors.

The cache keeps one epoch counter per dynamical factor — the resolved fields, the tracer positions — and a slot is readable exactly when its own epoch equals the counter it depends on.

The observables cache

The cache is the storage the iteration fills at its end with its observables: every read serves the deposited value or throws, and nothing is ever recomputed on a read.

GBGHomogeneousTurbulence.Cache.ObservablesCache — Type
ObservablesCache(domain; scalar = false, tracers = nothing,
                 particle_integration_scheme = nothing)

The observables cache of a run — the storage where each iteration deposits, at its end, the observables its own schedule produces: the velocity $\boldsymbol{u}$ and vorticity $\boldsymbol{\omega}$ in physical representation, the scalar $\varphi$ in physical representation when the run carries one, the fastest flow speed on the grid (the max_speed number the next timestep choice reads), and — when the run advects tracers — the flow velocity at the tracer positions $\boldsymbol{X}$, $\boldsymbol{u}(t, \boldsymbol{X}(t))$, at the current time and at the few earlier times the particle integration scheme works from.

The contents are automatic, derived from the configuration: the cache holds exactly what the iteration computes, materializes, and leaves alive at its end, and nothing more. The cache allocates and owns every slot, the velocity at the particles included — that sample is an observable of the flow, not particle state (a tracer has no velocity of its own), so its storage lives here and the tracer push writes into it exactly as the step writes into the field slots.

Build it on a FixedDomain domain. Simulation builds, wires, and seeds one for you.

Arguments

  • domain — the FixedDomain the run lives on; it sizes every field slot.
  • scalar = false — pass true when the run evolves a passive scalar, which adds the scalar's slot.
  • tracers = nothing — the Tracers the run advects; they size the trail of the velocity at the particles.
  • particle_integration_scheme = nothing — the scheme that advances those tracers, which fixes how many samples the trail keeps. Give both of these or neither.

Read through the accessors — velocity_physical, vorticity_physical, scalar_physical, velocity_at_particles_trail, and max_speed — each of which returns the deposited value or throws. Nothing in the cache is ever recomputed: a read that finds a slot stale, taken (in use as the step's own scratch mid-iteration), or never deposited throws an ErrorException naming the slot and its state — a scheduling error whose only repair is to fix the schedule that failed to deposit.

A cached array is the next iteration's scratch

A slot is also the array its producer computes in: between deposits the step writes its own stage values there, so a cached field is meaningful only between iterations. Treat every returned array as read-only — it is the storage the next iteration will work in.

Fields

The word epoch names two things here, and these fields are of both kinds. The two counters, fields_epoch and particles_epoch, rise as the state and the positions change; every other *_epoch field records the counter's value at the moment its slot was filled. A slot is readable exactly while the epoch it records still equals the counter it depends on.

  • velocity_physical, vorticity_physical — the cached velocity and vorticity in physical representation. Mid-iteration the step also writes each stage's velocity and vorticity into these same arrays, which is why they are not readable then.

  • scalar_physical — the cached scalar in physical representation, or nothing for a scalar-free run.

  • max_speed — the cached fastest flow speed (a host number in the field's own element type).

  • velocity_at_particles_trail — the ParticleTrail of the velocity sampled at the particle positions, or nothing for a tracer-free run.

  • velocity_epoch, vorticity_epoch, scalar_epoch, max_speed_epoch — the epoch each slot's value was deposited at, or a sentinel (never deposited / in use as scratch).

  • velocity_at_particles_epoch — the particles epoch the trail's newest sample was taken at.

  • fields_epoch — the resolved fields' counter, advanced by every completed step. A field-derived slot is readable exactly when its epoch equals this.

  • particles_epoch — the tracer positions' counter, advanced by every advect! push.

The checked reads

Each accessor returns the observable deposited at the current epoch, or throws; the cached maximum speed is read through max_speed, documented with the reduction it stores.

GBGHomogeneousTurbulence.Cache.velocity_physical — Function
velocity_physical(cache)

The velocity $\boldsymbol{u}$ in physical representation at the current epoch — the checked read of the ObservablesCache cache's velocity slot. Returns the deposited field when its epoch is current, and throws otherwise (the slot is mid-iteration scratch, stale, or was never deposited): the throw is an ErrorException naming the slot and which of the three states it is in, and nothing is ever recomputed on a read. Treat the returned field as read-only — it is the storage the next iteration works in.

source
GBGHomogeneousTurbulence.Cache.vorticity_physical — Function
vorticity_physical(cache)

The vorticity in physical representation at the current epoch — the checked read of the ObservablesCache cache's vorticity slot, with exactly velocity_physical's contract (the deposited field or a throw; never a recomputation; read-only). The deposited value is produced by vorticity_physical! — measure with that function, read with this one.

source
GBGHomogeneousTurbulence.Cache.scalar_physical — Function
scalar_physical(cache)

The scalar $\varphi$ in physical representation at the current epoch — the checked read of the ObservablesCache cache's scalar slot, on velocity_physical's terms (the deposited field or a throw; never a recomputation; read-only) plus one of its own: it throws an ArgumentError when the run carries no scalar, so there is no slot to read.

source
GBGHomogeneousTurbulence.Cache.velocity_at_particles_trail — Function
velocity_at_particles_trail(cache)

The flow velocity at the tracer positions $\boldsymbol{X}$, $\boldsymbol{u}(t, \boldsymbol{X}(t))$ — the genuine Lagrangian velocity, the input to the caller's statistics — as the ParticleTrail of its last few samples. trail[0].value is the velocity at the current time $t_n$, one vector per tracer, and trail[0].time is that time; trail[-1] is the sample one iteration back. How many samples the trail keeps is fixed by the run's particle integration scheme, whose docstring states it. Treat every value as read-only — it is the cache's own storage, and the tracer advance writes into it mid-iteration.

This is the checked read of the ObservablesCache cache: it serves the deposited samples or throws an ErrorException, like every cached read. The samples belong to the particles' time, so they are current exactly while the positions have not moved since the newest was taken. Throws an ArgumentError when the run advects no tracers.

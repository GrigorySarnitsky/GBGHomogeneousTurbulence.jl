Generator

GBGIsotropicTurbulence.Generator — Module
Generator

The flow's equations of motion — the incompressible Navier–Stokes right-hand side in rotational form (the dealiased, Leray-projected nonlinear term), the passive-scalar advection, and the exact viscous integrating factor.

Its contents (each formula lives in the operation's own docstring):

  • FlowConditions — the physical conditions the right-hand side is built from (the viscosity, the Schmidt number, the forcings).
  • ResolvedGenerator — the conditions bundled with the assembly scratch, consumed through the protocol below.
  • prepare! — open a step: advance the forcings' internal state and fill the linear rate arrays the integrating factors consume.
  • velocity_rhs!, scalar_rhs! — assemble the explicit right-hand sides (each dealiased term plus its additive forcing source) at a stage state.
  • velocity_integrating_factor, scalar_integrating_factor — supply each field's viscous/diffusive integrating factor, with any linear forcing rate folded in.
  • finalize! — apply the post-step forcing projections; the iteration closes later, at the deposit.

The assemblies recover displaced fields in physical representation with the four-argument, source-preserving form of to_physical! — the extra argument is a scratch field the transform consumes in the source's place — and with vorticity_physical!.

Flow conditions

The physical conditions the generator is built from — viscosity, Schmidt number, and the velocity and scalar forcings.

GBGIsotropicTurbulence.Generator.FlowConditions — Type
FlowConditions(; viscosity, schmidt, velocity_forcing, scalar_forcing)

The physical conditions the generator is built from — the kinematic viscosity $\nu$ (viscosity; $\mathrm{Re} = u'L/\nu$: with $u' = 1$ and the shipped $L = 2\pi$ the box-scale value is $2\pi/\nu$, and $1/\nu$ when lengths are measured in box units; the Reynolds number built on the integral scale is smaller still), the Schmidt number $\mathrm{Sc}$ (schmidt; the scalar diffusivity is $\varkappa = \nu/\mathrm{Sc}$), and the velocity and scalar forcing strategies (velocity_forcing, scalar_forcing, both AbstractForcing).

Not to be confused with Phenomenology's FlowParameters, which shares two field names: this type holds what a run is configured with, that one holds what a run has been measured to have.

Read through the ResolvedGenerator a scheme is handed — step! never holds conditions itself.

Arguments

All keyword, all required:

  • viscosity — the kinematic viscosity $\nu$.
  • schmidt — the Schmidt number $\mathrm{Sc}$.
  • velocity_forcing, scalar_forcing — the forcing strategies for the velocity and the scalar, each an AbstractForcing (pass NoForcing() to leave a field undriven).
A stateful forcing cannot drive both fields

Its per-step state belongs to one field, so passing the same mutable strategy instance as both velocity_forcing and scalar_forcing throws an ArgumentError naming it. Build two.

A defaulted controller settling time never drives the scalar

A VarianceController whose turnover_time was left at its default derives the settling time from a kinetic-energy law, which is meaningless for a scalar variance — passed as scalar_forcing with a positive gain it throws an ArgumentError. Pass the flow's turnover time explicitly.

Fields

The plain constructor FlowConditions(viscosity, schmidt, velocity_forcing, scalar_forcing) takes the four fields directly, in the order shown; each holds the value documented for the keyword of the same name above, with the two numbers stored as Float64.

The generator as one value

The right-hand side as one object — the conditions bundled with the assembly scratch its evaluations write through. A time-marching scheme consumes it only through the protocol below.

GBGIsotropicTurbulence.Generator.ResolvedGenerator — Type
ResolvedGenerator(domain, conditions; scalar = false)

The flow's generator as one value a scheme can hold. It carries the FlowConditions parameter record together with the assembly scratch its evaluations write through: the quadratic-product fields, the per-mode forcing-rate arrays, and — when the domain dealiases by PhaseShift — the displaced-evaluation buffers.

That scratch is the generator's own storage, distinct from the run's observables cache. The two do meet at one point: the physical quadratic products are formed in place over the cache's arrays, the Lamb vector over the vorticity slot and the scalar flux over the velocity slot, so no product field in physical representation is allocated anywhere.

A time-marching scheme consumes the generator through a fixed protocol: prepare! once per step, velocity_rhs! / scalar_rhs! at each stage state, velocity_integrating_factor / scalar_integrating_factor for the exact linear subflows, and finalize! after the completed step. The scheme does only stage arithmetic, so it can never assemble the right-hand side from a mismatched intermediate state.

Arguments

  • domain — the FixedDomain the assembly scratch is sized on.
  • conditions — the FlowConditions the generator resolves: the viscosity, the Schmidt number, and the two forcing strategies.
  • scalar = false — pass true when the run carries a passive scalar; it allocates the scalar's forcing-rate array, required for a scalar-forced run.

Simulation builds one for you.

The constructor rejects a misdeclared forcing

A forcing that implements set_forcing_rate! without also declaring uses_steady_linear_rate is given no rate array to fill, so its forcing would silently never be applied. Building a ResolvedGenerator around one throws an ArgumentError naming the strategy, rather than letting the run proceed quietly wrong.

One optimization crosses two verbs

Under PhaseShift, velocity_rhs! leaves the stage's displaced velocity fresh for the same stage's scalar_rhs! to reuse. Neither verb's signature carries the handoff: the generator records which û the displaced velocity was taken of, and scalar_rhs! reuses the scratch only when that record matches its own û and its caller promises through displaced_velocity_current that the scratch is still fresh. The record is opportunistic, never load-bearing — a mismatch only forces a redundant rebuild with the same value: a scalar_rhs! handed a different û than the recorded one rebuilds the displaced velocity itself, value-identically.

Fields

  • conditions — the FlowConditions parameter record ($\nu$, $\mathrm{Sc}$, the forcings).
  • product_spectral — the quadratic products' spectral image (the transformed Lamb vector $\boldsymbol{u}\times\boldsymbol{\omega}$, or the transformed scalar flux $\boldsymbol{u}\varphi$). In physical representation each product is formed in place over an operand's own array — the Lamb vector over the vorticity's, the flux over the velocity's — so no physical product array exists.
  • phase_shift — the displaced-evaluation scratch and translation kernels (PhaseShift dealiasing only), else nothing.
  • velocity_rate, scalar_rate — the per-mode linear forcing-rate arrays $A(\boldsymbol{\kappa})$. prepare! fills them at the start of each step; a rate that has been filled is one the integrating-factor verbs then return alongside the viscous coefficient, so the forcing rides the exact linear solve instead of being added afterwards. Each is nothing unless that field's forcing declares uses_steady_linear_rate, so a field driven by a post-step projection, a stochastic source, or nothing at all carries no rate storage; scalar_rate is also nothing for a scalar-free generator.
  • displaced_velocity_source — the û whose displaced velocity phase_shift.u_shifted holds, left fresh by velocity_rhs! for the same stage's scalar_rhs! (PhaseShift only). Reuse takes two conditions together: this record must match the caller's û, and the caller must promise through displaced_velocity_current that the scratch is still fresh. The record alone can only force a rebuild.

The generator protocol

One step of the dynamics, as the scheme sees it: open with prepare!, evaluate the right-hand sides and the exact linear factors at each stage, close with finalize!.

GBGIsotropicTurbulence.Generator.prepare! — Function
prepare!(generator, state, domain, dt)

Open a step of the generator: advance each forcing's internal state once (its per-step prepare_forcing! hook) and arm the per-mode linear forcing rates — fill them, so the factor verbs return them instead of nothing (its set_forcing_rate! hook, written into the generator's rate arrays). A scheme calls this once before its Runge–Kutta stages; the stage evaluations and the integrating factors then consume what it prepared.

The arguments are:

  • generator — the ResolvedGenerator being opened.
  • state — the start-of-step ResolvedFields the forcing hooks read.
  • domain — the FixedDomain the rates are formed on.
  • dt — the timestep the forcings prepare for.

Returns generator.

GBGIsotropicTurbulence.Generator.velocity_rhs! — Function
velocity_rhs!(N̂, generator, û, u, ω_consumed, domain)

Assemble the explicit right-hand side of the momentum equation into N̂ — the dealiased, Leray-projected rotational nonlinear term plus any additive forcing source. Two arguments are written, not one: N̂ receives the result, and ω_consumed is consumed in place — the _consumed suffix marks it, since Julia's ! convention flags only the first.

The arguments are:

  • N̂ — the field in spectral representation receiving the assembled term.
  • generator — the ResolvedGenerator whose conditions and assembly scratch are used.
  • û — the stage velocity in spectral representation, consulted by PhaseShift's displaced evaluation; a mask strategy leaves it unused.
  • u — the stage velocity in physical representation, only read.
  • ω_consumed — the stage vorticity in physical representation, consumed (see the note below).
  • domain — the FixedDomain whose dealiasing strategy and transforms assemble the term.

In physical space the rotational form writes the convective term as the Lamb vector, through the identity

\[(\boldsymbol{u}\cdot\nabla)\boldsymbol{u} = \nabla\bigl(\tfrac{1}{2}\lvert\boldsymbol{u}\rvert^{2}\bigr) - \boldsymbol{u}\times\boldsymbol{\omega},\]

so that, with the Leray–Helmholtz projection $\mathbb{P}$ onto divergence-free fields absorbing the pressure and the $\nabla\bigl(\tfrac{1}{2}\lvert\boldsymbol{u}\rvert^{2}\bigr)$ gradient, the momentum equation becomes

\[\partial_t\boldsymbol{u} = \mathbb{P} (\boldsymbol{u}\times\boldsymbol{\omega}) + \nu\nabla^{2}\boldsymbol{u} + \boldsymbol{f}.\]

The term computed is the spectral image of $\mathbb{P} (\boldsymbol{u}\times\boldsymbol{\omega})$, dealiased by the domain's DealiasingStrategy, plus the per-stage additive source of the generator's velocity forcing (its add_forcing_source! hook). A mask strategy (TwoThirds, HouLi) forms the term once from u, ω and multiplies by the low-pass domain.dealias, leaving û unused; PhaseShift forms it twice — from u, ω, and from the fields recovered on a grid displaced by half a cell (using û and the generator's displaced-evaluation scratch) — averages the two to cancel the aliasing, then truncates spherically with domain.dealias.

Two linear pieces are deliberately not in N̂: the viscous term and the exactly-linear part of a forcing are advanced exactly by the integrating factor (velocity_integrating_factor).

The advective term's $\kappa = 0$ mode is zeroed exactly ($\langle\boldsymbol{u}\times\boldsymbol{\omega}\rangle = 0$ holds discretely only to roundoff, and the mean mode has no viscous damping); the forcing source, added after, may carry a mean.

Returns N̂.

The vorticity argument is read and then overwritten

The Lamb vector is formed in place over the vorticity's array — the backend's cross product may write into one of its operands — so ω_consumed must hold the vorticity on entry and no longer does on return, while u is only read. This is what keeps a product field in physical representation from existing at all; passing a copy instead would cost a resident $N^{3}$ vector, which the package's preference for the smallest working set forbids.

Which operand is consumed follows the physics, not the argument position: the Lamb vector forms over the vorticity here, and the scalar flux over the velocity in scalar_rhs! — which is why both name the consumed argument rather than leaving a caller to infer it. Only the spectral product scratch remains on the generator, and the operation allocates nothing.

GBGIsotropicTurbulence.Generator.scalar_rhs! — Function
scalar_rhs!(N̂, generator, û, φ̂, u_consumed, φ, domain;
            displaced_velocity_current = false)

Assemble the explicit right-hand side of the passive-scalar equation into N̂ — the dealiased advection term plus any additive forcing source. Two arguments are written, not one: N̂ receives the result, and u_consumed is consumed in place — the _consumed suffix marks it, since Julia's ! convention flags only the first.

The arguments are:

  • N̂ — the field in spectral representation receiving the assembled term.
  • generator — the ResolvedGenerator whose conditions and assembly scratch are used.
  • û, φ̂ — the stage velocity and scalar in spectral representation, consulted by PhaseShift; a mask strategy leaves both unused.
  • u_consumed — the stage velocity in physical representation, consumed (see the note below).
  • φ — the stage scalar in physical representation, only read.
  • domain — the FixedDomain whose dealiasing strategy and transforms assemble the term.
  • displaced_velocity_current = false — the reuse promise for PhaseShift's displaced velocity, explained below.

In conservative form the advection is $-\nabla\cdot(\boldsymbol{u}\varphi)$ (equal to $-\boldsymbol{u}\cdot\nabla\varphi$ since $\nabla\cdot\boldsymbol{u} = 0$). The conservative form conserves the scalar mean exactly: the divergence has no $\boldsymbol{\kappa}=\boldsymbol{0}$ component, and the dealias kernel domain.dealias (the sharp $2/3$ rule by default) leaves that mode untouched.

The term is computed pseudospectrally as $- \operatorname{dealias}\bigl(\mathrm{i}\boldsymbol{\kappa}\cdot\widehat{\boldsymbol{u}\varphi}\bigr)$, plus the per-stage additive source of the generator's scalar forcing (its add_forcing_source! hook).

The dealiasing strategy controls the aliasing of the quadratic product. A mask strategy (TwoThirds, HouLi) forms the flux once from u_consumed, φ, leaving û and φ̂ unused. PhaseShift instead averages it with the flux recovered on a grid displaced half a cell — using φ̂ and the generator's displaced-evaluation scratch, and reading the displaced velocity the same stage's velocity_rhs! left fresh there (a bare scalar_rhs! with no preceding velocity evaluation rebuilds it from û instead) — before the spherical truncation.

The diffusion $\varkappa\nabla^{2}\varphi$ and the exactly-linear part of a forcing are not in N̂: they are advanced exactly by scalar_integrating_factor.

Pass displaced_velocity_current = true only if nothing has changed since this generator's velocity_rhs! was called on the same û — a time-stepping scheme knows this because it evaluates both right-hand sides at one stage before updating either field; a hand-written caller generally does not. Reuse needs both the keyword and the generator's recorded source matching û. The record alone can only force a rebuild, never a wrong reuse; the keyword is the load-bearing half — containers are rewritten in place, so a false promise over the same container is quietly wrong, where the default merely rebuilds (one shift, three inverse transforms) and stays correct.

The advective term's $\kappa = 0$ mode is zero exactly by construction — the divergence multiplier $\mathrm{i}\boldsymbol{\kappa}$ vanishes identically at $\boldsymbol{\kappa} = \boldsymbol{0}$ — and the assembly pins it anyway, for uniformity with the velocity route, whose product mean is only roundoff-small; the mean of $\varphi$ has no diffusive damping. The forcing source, added after, may carry a mean.

Returns N̂.

The assembly consumes the velocity argument

The flux $\boldsymbol{u}\varphi$ is formed in place over the velocity's array (a pointwise product may write into an operand), so on return u_consumed no longer holds the velocity; φ is only read. As in velocity_rhs!, the consumed argument is fixed by the physics rather than by its position in the signature, and is named for it. Only the spectral product scratch remains on the generator, and the operation allocates nothing.

GBGIsotropicTurbulence.Generator.velocity_integrating_factor — Function
velocity_integrating_factor(generator, τ)

The velocity's exact linear subflow over a substep $\tau$ (τ), as the parameters of its exponential rather than a materialized kernel. The generator (a ResolvedGenerator) supplies the viscosity $\nu$ and the armed rate; τ is the sub-interval the stage advances.

The linear part of the momentum equation — the diffusion $\partial_t\boldsymbol{u} = \nu\nabla^{2}\boldsymbol{u}$, plus any linear forcing rate $A(\boldsymbol{\kappa})$ that prepare! armed — is solved exactly in spectral representation by the per-mode multiplier

\[\mathcal{E}(\boldsymbol{\kappa}) = \exp\!\bigl((A(\boldsymbol{\kappa}) - \nu\lvert\boldsymbol{\kappa}\rvert^{2}) \tau\bigr),\]

with $A = 0$ when no linear forcing is active. Multiplying a field by $\mathcal{E}$ advances its viscous (and linear-forcing) part exactly — machine-exact, with no stability restriction; only a scheme's explicit stage combination carries truncation error.

Since the multiplier is the exponential of a radial symbol plus the armed per-mode rate, a scheme applies it through the backend's fused exponential convolution (exponential_convolve!), which evaluates it per mode from the wavenumber arrays: nothing is built, stored, or swept for it. Returns a named tuple (; coefficient, offset_scale, offset) — exactly the arguments that fused exponential takes: $\texttt{coefficient} = -\nu\tau$ (the factor on $\lvert\boldsymbol{\kappa}\rvert^{2}$), $\texttt{offset\_scale} = \tau$, and $\texttt{offset} = A(\boldsymbol{\kappa})$ (the armed rate field, or nothing when no linear forcing is active).

GBGIsotropicTurbulence.Generator.scalar_integrating_factor — Function
scalar_integrating_factor(generator, τ)

The passive scalar's exact linear subflow over a substep τ — the same exponential parameters velocity_integrating_factor returns for generator, with the scalar diffusivity $\varkappa = \nu/\mathrm{Sc}$ in place of $\nu$ and the scalar forcing's armed linear rate in place of the velocity's.

GBGIsotropicTurbulence.Generator.finalize! — Function
finalize!(generator, state, domain)

Close a step of the generator: apply each of its forcings' post-step projections (the project_forcing! hook — e.g. the energy rescale of a VarianceRescaling) to the advanced state, velocity first, then the scalar when the run carries one. A scheme calls this once after its final stage, so everything that follows the step — the diagnostics, the derived observables, the tracer advance — sees the forced end-of-step fields. The name is this protocol's step-closing verb, unrelated to Base.finalize, Julia's garbage-collection finalizer vocabulary.

The arguments are:

  • generator — the ResolvedGenerator whose forcings project.
  • state — the advanced ResolvedFields the projections act on.
  • domain — the FixedDomain they act over.

Returns state.
